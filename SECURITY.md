# Security

Security fixes target the latest release.

Use **Security → Report a vulnerability** on GitHub for private reports. If unavailable, open an issue requesting a private contact without posting exploit details or secrets.

Include the version, OS, reproduction steps, and impact. Remove credentials and private code from attachments.

Agents run with your user permissions and can read files, edit code, and execute commands. Providers receive the context sent to them, including attached files and unsaved editor content. Closing the window leaves background agents and schedules running; stop them in Ramu when needed.

## Remote access

A device paired with full access can read workspace data, run agents and terminals, edit files, and use the host's provider credentials. Pair only devices you trust. A viewer can read conversations and answer approval/question requests; approving a request can authorize the agent to execute it. Viewer access is therefore intended for trusted reviewers, not public sharing. The desktop composer disables sending, Stop/Resume and host attachment uploads on a viewer host and explains why. The thread queue remains readable with host send/edit/remove/reorder/resume controls disabled; local outbox cleanup stays available. Goal, model/access, provider-routing, retry and auto-resume controls also stay read-only. Host role reads are shared, scoped to host identity and retain a confirmed viewer restriction when a new connection fails. Helper stop/message actions, aside creation/deletion, sent-message editing and rewind, and header command/continuation actions also respect viewer access; existing helper/aside transcripts remain readable and local drafts survive role changes. Host preference fields are disabled for selected viewer hosts; retained settings action callbacks recheck the latest selected host and role, and status-read failures retain a confirmed viewer restriction. Computer Use settings show the access explanation for a selected viewer host; retained computer enable/reset/sharing callbacks also recheck access. Browser settings keep device-local link/search preferences and local profile administration usable while host preferences and Host Browser administration become read-only for viewers. Provider configuration is read-only as well, and a login command returned after an access change cannot launch a setup terminal. Agent-setup and MCP administration also retain the viewer restriction when a cached status says administration is available. Environment drafts become read-only without being discarded; environment reads, saves and draft callbacks stay bound to their selected host/load key, and late or out-of-order reads cannot replace another host’s values. Rules switches, deletion and editors respect viewer access, retaining open drafts; rule history caches include the host and retained save/restore callbacks check their originating host. Installed-skill drafts and source-update reviews become read-only for viewers; saved approvals remain readable with removal disabled. Settings routes change identity when their host/readiness snapshot changes so host-bound panels reload; retained routes refuse a different host instead of forwarding old IDs there. Learning maintenance and managed-skill mutations also check current access; cached reviews remain readable, and host-tagged, ordered refreshes cannot replace another host’s snapshot or a newer reading. Mobile host-browser entry points explain viewer access without polling forbidden methods. An open phone browser keeps its address draft while disabling its view and retained navigation until full access returns. Owner-granted computer screens remain watchable on desktop and phone viewer devices through the permitted session/frame/video methods, without administrative status reads. Input, takeover, handoff answers, Stop, revocation and sharing controls are unavailable; retained actions recheck access and leave unsent text intact. The desktop host browser likewise stops polling and hides its interaction surface for viewers while retaining drafts. Navigation and download callbacks recheck access and host/thread identity; download popups close while access is restricted without discarding their local paths. File and Git panels explain viewer restrictions while preserving mounted rename and commit drafts. Both cached and uncached file/Git RPC paths refuse confirmed viewer access; out-of-order status replies cannot restore an older owner role. Repository queries pause, open file/Git confirmations become read-only, and retained confirmations and commit shortcuts recheck access. Open file editors retain unsaved buffers behind the access notice; save shortcuts and file-change refreshes recheck access. Existing terminal views hide their input surface for viewers, and retained keystroke, drop, menu-paste, resize, startup and reconnect callbacks recheck access. Terminal RPCs also refuse confirmed viewer access before transport, while native terminal menus remain device-local. Terminal reconciliation pauses for viewers. Tabs first opened while restricted can load or attach after full access returns. Device-local host management remains available.

These client controls are a convenience, and the host still refuses every disallowed request.

Mobile schedule lists and details retain read access while hiding create/edit and swipe mutations and disabling run, pause and delete. Edit deep links explain the role and preserve an existing local draft. Mobile helper messages and side-question drafts remain visible but read-only; helper Stop and side-question create/delete controls are hidden for viewer hosts. Mobile message menus keep Copy and Quote while hiding sent-message edit/resend, file undo and Ask aside; menu callbacks recheck the role even after a native action sheet opens. Thread pin/rename/archive/delete actions and swipe mutations are hidden for viewers; desktop row/header actions, bulk updates and project archive/routing actions also check current access and host identity. Bulk updates recheck before each thread, and open rename/routing drafts become read-only without being discarded. Deletion dialogs disable confirmation and avoid loading command records for viewers. Archived history stays readable while bulk deletion is hidden and its retained confirmations are guarded. Retained action and deletion callbacks are guarded. Retained send and destructive confirmation callbacks recheck the current role and connection. Mobile project menus keep copy-path and local new-thread drafts while hiding host file, terminal, rename, routing, command-management and removal actions for viewers. Already-open rename/routing drafts and cached command settings become read-only; retained save/removal and delayed navigation callbacks recheck role and target. Mobile RPC dispatch shares the host’s explicit viewer allowlist, including permitted approval/question answers. Viewer access blocks new send/outbox creation, pauses queued delivery before transport and preserves pending text when the role changes during the delivery yield. Paused items stay visible with the access explanation and local cancel/edit recovery. Missing access fields on reconnect retain a confirmed role. Schedule callbacks recheck the current host role and connection before issuing an RPC, including callbacks retained across a role change; the host remains the authority.

Expose the server only on a trusted LAN/VPN or through authenticated HTTPS/tunnelling. Ramu has no relay or end-to-end encryption. HTTP sends bearer credentials and workspace data without application-level encryption. Native mobile certificate pinning is still unfinished; use a trusted HTTPS certificate or your own authenticated VPN.

Create a full-access pairing with `ramu pair`, or a viewer pairing with `ramu pair --role viewer`. The role is bound to the single-use code by the host. List devices with `ramu devices`; revoke a lost device in Settings → Remote access or with `ramu devices revoke <id>`. Use `all` to revoke every paired device. Revocation also closes its event streams.

Device credentials expire after 90 days of inactivity by default. Authenticated activity extends their expiry. Paired desktop and mobile clients also rotate the secret about monthly: `POST /renew` with the current token returns a fresh one, the client saves it before use, and the host retires the old token two minutes after the new token's first use (an unused renewed token is dropped after seven days, and a lost response just means asking again). Hosts that predate renewal keep the original token. Set `RAMU_DEVICE_TOKEN_DAYS` to positive days or explicitly to `never` on the server to choose a different policy. Existing records use their last recorded activity for migration, so inactive old devices may need pairing again. The CLI and host Settings show expiry.

Legacy shared bearer authentication is disabled unless `RAMU_ALLOW_LEGACY_TOKEN=1` is set. Prefer per-device pairing so access can be individually revoked. Browser access is disabled by default; set `RAMU_BROWSER_ORIGINS` to a comma-separated list of exact trusted HTTP(S) origins to enable it. Origin checks supplement bearer authentication.

## Theme editor preview

The desktop Code/Diff theme preview runs app-authored Monaco code on a separate `ramu-theme:` origin. Its protocol serves only the preview entry and bundled renderer assets, with real-path checks against symlink escapes; development requests are limited to source modules in the checkout and the configured Vite server. It cannot load workspace files, invoke the native bridge or read the parent window. Native frame checks restrict its entry and reject navigation to arbitrary destinations. The frame allows scripts and its own origin for Monaco workers; that origin differs from the workspace. Its policy restricts scripts, workers and connections to its own assets and forbids nested frames, objects and form submission.

Parent messages carry validated palette, appearance and local view choices only. Source, paths, commands and executable-looking extra fields are discarded. Both directions check the frame identity, and request ordering prevents an older asynchronous palette result replacing a newer one. Samples are read-only and have no host persistence or provider calls. Generated interactive documents keep their separate `ramu-content:` policy and cannot use this origin as a host API.
