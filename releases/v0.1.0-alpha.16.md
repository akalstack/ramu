# Ramu v0.1.0-alpha.16

## Added

- Account, reworked: **Settings → Account** leads with who is signed in, or with what the account adds and one **Sign in**. A sign-in in progress shows its code, **Open the sign-in page** and that Ramu is waiting. Backups are two switches with the last backup and **Back up now** beside them, **Restore…** is one dialog from getting the key to choosing a backup, and the recovery code, deleting backups and deleting the account are under **Advanced**. See [Ramu account](https://github.com/akalstack/ramu/blob/main/docs/guide/account.md).
- Devices on your Ramu account: whether your phone and computers signed in to the account connect to a host is now one choice in **Settings → Remote access**, beside **Pair a device**: full access, view-only, ask here first, or off. Listed hosts this computer doesn't use yet show under **Hosts you use**.
- Pairing through the tunnel as a backup: a pairing link or QR code that carries a local address also carries the host's tunnel address, and a phone or computer that can't reach the local one (scanned away from home) pairs through the tunnel. Only a tunnel's https address is added, so the code never goes to an address that could belong to someone else.
- Network choices name the tunnel: the network switch and the phone's address list say **Ramu Link**, **Quick tunnel (Cloudflare)**, **Tailscale** or **ngrok** instead of "Other network", and the pair dialog names each address's network.
- `/btw` is listed beside `/aside` in the message box's commands, on the desktop and the phone.

## Fixed

- Ramu Link: hosts got "relay-error" and never an address. The relay could not create tunnels; it is fixed on the relay, and the address now arrives within seconds.
- Ramu Link: after signing in, Settings kept asking to sign in until Ramu restarted. The host now asks the relay as soon as you sign in, and after an error it asks again on its own, waiting longer each time.
- Ramu Link: an offline host no longer takes one of the relay's places, so far more accounts can keep an address; a host coming back while the relay is full waits in line under the same address. The warning names the relay's reason in words, and **Recommended** shows as a badge.
- Signing in: if reading your profile failed right after you approved, the page stayed on the code. It now tries again, and returns to **Sign in** if the account service still does not answer.

## Downloads

Choose the installer matching your OS and CPU: macOS arm64 (Apple Silicon), macOS x64 (Intel), or Linux x64 or arm64 (.deb, .rpm, AppImage or ZIP). SHA256SUMS files accompany the downloads.

## Known limitations

Desktop alpha. macOS builds update themselves; Linux installs outside a package manager update by hand. Windows releases are not available yet. Agent providers require their own installation and authentication. Ramu Link traffic passes through Cloudflare; every call still needs a paired device.
