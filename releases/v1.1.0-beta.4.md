# Ramu v1.1.0-beta.4

## Added

- **Ship does more without stopping for you, and each project chooses how much.** Under **Ship** in a project's **Live app…** sheet, on the desktop and the phone: **Send replies that report a fix** (on) pushes the branch and posts those replies after a review round, with **Undo** in the thread; **Merge when approved** (off) turns on the Git host's own auto-merge; and after a project's first production deploy, later ones run without the card. A repository's `ramu.json` can keep any of these with a person ([Shipping a change](https://github.com/akalstack/ramu/blob/main/docs/guide/git-hosting.md#shipping-a-change)).
- **From an idea to a live address in one ask.** Asked to build something and put it live, the agent creates the project, publishes it to a private repository, picks a deploy platform, deploys and gives Ramu the address, which is saved as the project's live address and checked at once. It stops only for a token or secret and the first production deploy; outside Full access it asks before publishing.
- **A pull request says what it is waiting on.** In place of **Waiting on review**, rows, the pull request's header, Source Control and the phone say on whom and for what: "needs 1 more approval from @payments-team", "needs a code owner's approval", "2 conversations to resolve". Ramu reads this from GitHub's rulesets, GitLab's approval rules, Azure DevOps's required reviewers and Bitbucket's reviewers. A shipping thread that waits on reviewers spends no turns, offers reviewers once when nobody was asked, drafts a reminder after a working day, and says when an approval no longer stands. Inbox's Brief lists a pull request nobody was asked to review, with **Request review**.
- **Merge shows only when the Git host can take it.** A pull request held by a rule offers **Merge when ready…** where the service merges on its own, and no Merge elsewhere. On a GitHub branch with a merge queue, the dialog offers **Add to merge queue**.
- **Commits and comparisons open as changed files.** **View full commit** and **Compare with** the upstream show each file's diff as a pull request's **Files changed** does, under the commit's message, instead of Git's printout. A comparison shows what the branch adds since the two parted. Tick **Viewed** on a file to fold it and keep count; a pull request's **Files changed** has the same tick. **Open on the hosting service** shows a pushed commit on GitHub, GitLab or Bitbucket.
- Source Control's commit list shows commits the upstream has and this checkout does not, first, with a down arrow (**not pulled** on the phone).
- A queued message can be edited in the message box before it goes out.
- On the phone, select text in a terminal as you do in a chat, with **Select all** and **Select command**.
- A sign-in that runs in a terminal (a provider's login, `gh auth login`) opens it on the host with the sign-in page, and closes itself once it succeeds.

## Changed

- **A connection that drops for a moment picks up where it stopped.** A device back within 45 seconds is sent exactly the events it missed, in order, and the desktop no longer reads everything again. After a longer gap it reads again what it shows, and the host reads **Syncing…** until that is done. A message sent as the connection drops is delivered once, a failed send stays in its thread after you close it, and a thread far behind catches up in parts.
- A review round waits until the reviewer has left no new comment for five minutes, so the agent answers the whole review at once.
- A running turn counts **Working for** at its top, with its steps under it, and work the agent picks up by itself reads **Worked for**.
- A thread's toolbar keeps its buttons in place while the thread loads, and **Commit & Push** reads as one control with its arrow.
- Resolving a conflict works in a narrow pane: the sides stack by the width of the view, each with its own **Accept** button.
- The **Changes** tab opens in one step, and dragging down the line numbers marks the lines as a block while you write the comment.
- **Install as app** is offered for App artifacts only; a doc, deck, diagram or dashboard still opens in its own window.
- Decks no longer have **Present**. Export a deck as PowerPoint or PDF and present it in the app you use for that.
- The phone gets no push while you are using the desktop app.
- **Computer** and **Test devices** settings no longer offer **All hosts**, and Plan usage calls this computer **This host**.
- Setup labels the default agent, searches long model lists and keeps effort in view.
- In Full access, a command is judged from the folder its line has moved to: cleaning up under the temporary folder after `cd /tmp/…` no longer asks, and `cd /` followed by a relative removal does.

## Fixed

- Sending and steering no longer make the chat jump: a sent message keeps its place and size, a new thread from Home never shows an empty frame, and the transcript shows one scrollbar.
- The working highlight on a label no longer restarts or flashes, and replies stream a Markdown block at a time again.
- Sent answers show the choices that were offered, with the picked ones marked, on the desktop and the phone.
- A changes card stays where its work ended instead of sliding under later messages.
- A thread on another host shows its **Servers**, **Resources** covers that host, and Settings pages no longer flash **Checking…** on each visit.
- Setting up computer use, test devices and skills finds Node from a version manager (fnm, nvm) in the released app.
- A dragged row in the sidebar stays where it is dropped.
- A folder link outside the thread's folders opens its project, or shows in the file manager.
- A host with many change reviews no longer answers with a list too large to send, and one oversized answer can no longer drop the connection.
- A desktop that falls behind on events catches up on the same connection instead of showing **Reconnecting…**.
- Inline code has room around its text, and **Limited** no longer runs into **Switch login**.

## Downloads

Choose the installer matching your OS and CPU: macOS arm64 (Apple Silicon), macOS x64 (Intel), or Linux x64 or arm64 (.deb, .rpm, AppImage or ZIP). SHA256SUMS files accompany the downloads.

## Known limitations

Desktop beta. macOS builds update themselves; Linux installs outside a package manager update by hand. Windows releases are not available yet. Agent providers require their own installation and authentication. Ramu Link traffic passes through Cloudflare; every call still needs a paired device. A database from this release opens only in this release or later. A host on this release and a device on an older one work together, without event replay until both are updated.
