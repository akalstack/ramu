# Ramu v0.1.0-alpha.5

## Fixed

- Settings: after an app update, the background service row no longer says "Matches the installed app" beside an older version number. When the service runs the same code but started under an earlier release, it says so and shows the older version until the service next restarts. Restart app & service is still offered only when the service code differs.
- Antigravity: installing the runtime no longer falls back to **Install runtime** with a failure that only says it "did not answer". The first start of the downloaded runtime can take minutes on an Intel Mac, so Ramu now waits up to five minutes, and a failure names how long it waited and the last thing the runtime printed.
- Antigravity: an install that is still running on the host keeps showing **Installing…** after you leave and reopen Settings, and the card updates by itself when the install finishes.
- Providers: when OpenCode, Codex, Antigravity or Cursor stops, Ramu now says why instead of "exited (signal)". A crash from an illegal instruction explains that the processor is probably too old for that build, as on older Intel Macs, and every stop includes the last line the program printed. Antigravity also gets five minutes to answer its first start.

## Downloads

Choose the installer matching your OS and CPU: macOS arm64 (Apple Silicon), macOS x64 (Intel), or Linux x64 or arm64 (.deb, .rpm, AppImage or ZIP). SHA256SUMS files accompany the downloads.

## Known limitations

Desktop alpha. Linux installs are told about new releases and installed by hand. Windows releases are not available yet. Agent providers require their own installation and authentication.
