# Ramu v0.1.0-alpha.3

## New

- Ramu updates itself on macOS. **Auto-update Ramu** is on by default: it downloads a new release a day after it is published, checks it and installs it when you restart Ramu. Alpha builds follow every newer release, beta builds follow beta and stable releases, and stable builds follow stable releases only.
- **Remove project** asks once and deletes the project's threads with it, archived ones included, instead of asking you to delete every thread first. Folders, worktrees and branches stay on disk.
- New thread: the host, project and checkout chips sit at the right of the message box.

Install this release by hand once; Ramu installs later releases itself. If you used an earlier alpha, turn on **Settings → System → Auto-update Ramu**.

## Fixed

- macOS: the first start after installing no longer stops with "Background service could not start" on slower Macs, Intel especially. Ramu shows a **Starting Ramu** window while macOS checks the new app, which can take up to a minute.
- Pull requests: images in comments, such as a review bot's buttons, show as their text instead of broken images.
- Settings: **Back up settings → To my Ramu account** can be ticked while signed out. It starts sign-in and turns the backup on once you are signed in, instead of doing nothing.
- Ramu reopens at the size and place you left it, maximized too, instead of 1440×900 every time.
- Setup: the step line no longer squeezes into one word per line beside the language picker, the identity cards line up, and a model OpenCode names twice ("9router/9Router Auto") shows its name once.

## Downloads

Choose the installer matching your OS and CPU: macOS arm64 (Apple Silicon), macOS x64 (Intel), or Linux x64 or arm64 (.deb, .rpm, AppImage or ZIP). SHA256SUMS files accompany the downloads.

## Known limitations

Desktop alpha. Linux installs are told about new releases and installed by hand. Windows releases are not available yet. Agent providers require their own installation and authentication.
