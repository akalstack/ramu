# Ramu v1.1.0-beta.8

## Added

- **Set up another host from your device.** A phone or computer with full access and that host's **Change settings** permission can now set up the host's providers, API keys, environment variables, media keys, shared MCP servers and their sign-ins, plugins, Git hosting accounts, browser and profiles, and computer use, without walking to it. These carry sign-ins and keys, so the connection must be encrypted (HTTPS, Ramu Link or another tunnel, or Tailscale); over plain HTTP the host refuses and says why. Installing computer use, turning on work through a locked screen and importing another browser's profiles still happen on the host, where the system asks for them.
- **One repository, one project, across hosts.** With **All hosts** chosen, a repository checked out on several hosts shows once, on the phone's thread list and under **On several hosts** in the desktop sidebar, each thread naming its host. Its menu and **New thread** go to the host it was last worked on. **Separate by host** in the host picker shows each host's copy on its own. A project with no remote stays with its host.
- **Follow checks after a push** (Settings → Git, on the desktop and the phone) turns off following a pushed commit's checks. It is on by default.
- **Send videos from the phone.** The photo library and the camera offer videos as well as photos, and a video up to 100 MB goes to the host in parts. The host now keeps `.mov` and `.m4v` as video too.
- **Videos and recordings play in the thread.** On the phone a video plays with the phone's own player, picture in picture included; on the desktop video and audio play in the attachment preview. Both stream from the host, so seeking works without downloading first.
- **Long lists keep going.** A schedule's history lists all its runs with **Show earlier runs**, Artifacts loads more as you scroll however many there are, with search and kind applied on the host, and message search shows more hits, on the desktop and the phone.
- In the phone's settings, **Sub-agents** can name one model for every helper, and each provider's **Automatic updates** can be turned off, as on the desktop.

## Changed

- **The phone's thread scrolls as T3 Code's does.** The list itself keeps the end of the thread above the message box and the keyboard as rows arrive, grow or fold. It opens at the end, and earlier turns load without moving what you are reading.
- **The phone's message box empties the moment you send**, and your words come back only if the send fails. A message on its way shows its pictures and files at once, and **Pin**, **Mark done**, **Archive** and **Rename** change the row at once while the host makes the change.
- **The phone's terminal** keeps its shell tabs and actions at the bottom over one slim key bar, and Backspace and the bar's arrows repeat while held.
- Selecting text in a phone message offers **Copy** first, then **Quote**, **New thread** and **Ask aside**, on iPhone and Android.
- **The aside answers on the model and login you pick in it.** Its message box has the thread's own model menu, login included, starting on what the thread runs, on the desktop and the phone. On the phone the aside uses the thread's message box, so you can attach files to a question.
- **A sub-agent opens as a thread does**: its task, then its own messages, thinking and tool calls in the thread's rows, with the thread's message box. On the phone it has a screen of its own with **Stop** in the bar; on the desktop it opens beside the thread and follows its latest output.
- **Long threads and lists stay quick.** The desktop transcript, sidebar threads, pull requests, Source Control's changes, Artifacts and the sub-agent panel draw only what is near the view, as do the phone's thread list, pull requests, search, Source Control, **Changes**, Artifacts, folders, file tree, file viewer and side questions. A thread still opens at its end or where you left it, and **Find** still reaches every loaded turn.
- **Full access asks only what the agent itself asks**, as in T3 Code, plus a deploy to production; the card says why in one line.
- **`/mcp` on the phone opens the thread's MCP servers**, where a server is signed in, as on the desktop.
- **A turn's edited files show when it ends**, without waiting for background commands such as a dev server. Changes still wait for sub-agents, which may edit after the turn.
- **Phone sheets go one level deeper with a back arrow** instead of stacking another sheet: a command's output, an activity reached from **N more**, and a provider's models.
- The phone's working label breathes instead of sweeping. **Background terminals** shows each command's state and time, a file on its way shows as an **Uploading** chip, queued messages read on two lines, the queue sheet steps aside for **Edit**, **Send now** and **Steer**, and the **Agents** chip counts agents at work, as on the desktop.
- The phone lists projects in the host's order, the one the desktop shows, and a project's menu has **Move up** and **Move down**.
- The phone's thread list says it is syncing beside its first heading, where it covers no thread.
- **Every row in the phone's thread list is two lines**: the title, then what the thread is doing or came to, with small marks for its pull request, agents at work, commands it waits on and an unreachable host. A command the agent waits on shows as a terminal, not an agent, on the phone and in the desktop's thread preview.
- A picture attached in the phone's message box opens full size before sending.
- The terminal's cursor pad on the phone is a round glass pad with plain arrows, raised on Android.
- **Make a release note** and **Make a launch deck** left the project menu; ask a thread for them instead.

## Fixed

- **The desktop uses much less energy while an agent works.** A label at work no longer repaints the window every frame, and a thread's servers are read every few seconds only while its window is in front.
- **The phone runs cooler while a thread is open.**
- **Threads get their names again.** A title is drafted on the thread's own model at its lightest effort, so it no longer fails on a model set to think hard, which left threads named after their first message.
- Signing in to a Codex thread's MCP server from another device finishes with the pasted `localhost` address.
- A message sent from the phone keeps its shape, with the time it was sent, as the host's copy takes its place.
- A running turn's replies on the phone show their time and **Copy** once the turn ends, so rows no longer grow while the agent works.
- Opening a thread on the phone stays covered until its latest rows and change cards arrive, so it no longer rearranges itself just after it shows.
- On the iPhone a finished turn no longer rests with its last lines under the message box, scrolling down by hand leaves no empty room, and the last line stays above the message box with the keyboard up.
- The phone scrolls as T3 Code does: it follows the end without gliding and no longer moves to an answer's start when a turn ends.
- A pushed branch whose pull request is watched (by you, **Automatically watch pull requests** or Ship) reports its failing checks once, not twice.
- An error from **Take control** or another action in the computer or browser viewer, on the phone and in the desktop's host browser, stays until you close it or act again, instead of vanishing within a second.
- The phone's **Changes** screen says it is loading instead of showing no changes, and a file opened from a thread's card closes on the first tap.
- A running step on the phone leaves one line under it, not two, and the terminal no longer shows iOS's form bar over the keyboard.
- The phone's compact-before-sending choice is an icon beside the microphone, so the model's name keeps its place.
- A phone settings page with panels of its own, such as **Agent setup**, no longer ends with a note that its host offers no settings there.
- Typing an answer in the phone's question sheet brings **Submit** into view above the keyboard.
- Swiping a thread row on the phone keeps up with the finger.
- **A long thread opens instead of failing with an answer too large to send.** The host sends a long thread's messages in parts to the phone and the desktop.

## Downloads

Choose the installer matching your OS and CPU: macOS arm64 (Apple Silicon), macOS x64 (Intel), or Linux x64 or arm64 (.deb, .rpm, AppImage or ZIP). SHA256SUMS files accompany the downloads.

## Known limitations

macOS builds update themselves; Linux installs outside a package manager update by hand. Windows releases are not available yet. Agent providers require their own installation and authentication.
