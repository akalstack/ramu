# Ramu v1.1.0-beta.7

## Added

- **Schedule a message into a thread.** **Schedule a message…** in a thread's menu, on the desktop or the phone, sends its prompt into that thread on each run, with the thread's own agent and settings, instead of starting a new thread. A run waits behind a turn already at work, and an agent asked to check back later can set one on its own thread.
- **A background command that ends says so.** When a command the agent left running in the background finishes or fails, a quiet line marks where it ended, on the desktop and the phone.
- **Permissions you allowed stay in the desktop transcript** as a quiet **Allowed** line with the command, as on the phone, with **Forget** for a rule you saved.

## Changed

- **Open a file attached to a message on the phone.** Tap it in a message, or in the message box before sending, to read its text, as the desktop's preview does. Pictures still open full size.
- **A turn you stop reads as stopped, not failed.** After **Stop**, the transcript says **Stopped after …** with no **Agent failed** row, the agent stays ready for your next message, and the thread lists show the thread as **Stopped** instead of **Failed**, on the desktop and the phone. A turn that fails on its own still shows as failed.
- **Dragging a folder onto the project list** shows the same drop overlay as files dragged into a chat, saying **Drop to add as a project**.
- An answered question reads like the agent's other activity: each question in full under **Answered 1 question**, with the answer you gave under it, instead of a cut-off line with the answer off to the right.
- In the desktop sidebar, a thread's status mark sits under its project's folder icon, so every title starts at the same edge and the age stays at the right.
- The phone's chips above the message box keep fixed names with a count (**Terminals · 2**, **Agents · 1**, **Servers · 1**), as the desktop's do, so they no longer change width as work moves.
- The phone's status lines carry a mark for what they are about, as the desktop's do: context compacted, resumed after restart, a stop, a schedule, advice and answers.
- A phone sheet closes by itself once what it shows is gone: the last question answered, the goal cleared, the queue sent, or the agents or the last server finished.
- Search in an iPhone sheet, such as the model picker, is a field under the title instead of a button floating over the list.
- A working tool group keeps one line under its headline for its latest thought, on the desktop and the phone, so the end of the chat holds still as thoughts and steps come and go.

## Fixed

- A running turn on the phone shows **Working for …** once, at its top; the line at its end says what the agent is doing.
- The phone's **Syncing messages…** pill floats just above the message box, in the same glass as the composer.
- Opening a thread on the phone shows it already at its end: it stays covered until its rows have measured, instead of scrolling into place in view.
- The phone keeps following new output while you are at the end of a thread.
- A finished tool group on the phone no longer keeps shimmering after newer rows arrive below it.
- No gap is left under **Thinking** when a long thought moves into a tool group's headline, on the desktop and the phone.
- A message sent from the phone keeps its height as the host's copy takes its place, instead of jumping by a line.
- The phone's message box clears after sending; only words or files added while the message was on its way stay.
- The phone's thread list no longer marks every thread **Offline** while it is still connecting to its host after the app opens; only a host that can't be reached does.
- **Drop to add to the message** over a chat is translated.

## Downloads

Choose the installer matching your OS and CPU: macOS arm64 (Apple Silicon), macOS x64 (Intel), or Linux x64 or arm64 (.deb, .rpm, AppImage or ZIP). SHA256SUMS files accompany the downloads.

## Known limitations

macOS builds update themselves; Linux installs outside a package manager update by hand. Windows releases are not available yet. Agent providers require their own installation and authentication.
