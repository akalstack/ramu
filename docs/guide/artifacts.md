# Artifacts

Agents can publish small interactive documents in a thread: explanations, diagrams, data explorers, calculators and prototypes. Their controls run locally with no further model call. A document you want to keep becomes an **artifact**: listed under **Artifacts** on the desktop and the phone, opened without its thread, changed by asking in any thread, and able to keep records and use your host's AI when you allow it.

## Kinds

The agent picks the kind from what you ask for. Each artifact's kind shows as a small mark on its row under **Artifacts** and on its card in the thread, and **Artifacts** on the desktop can be filtered by kind.

| Kind | What it is | Exports |
| --- | --- | --- |
| **App** | Interactive web content: calculators, trackers, explorers, games | HTML, source, PDF |
| **Doc** | Writing to keep: a report, plan, spec or notes, written in Markdown with tables, task lists, footnotes, Mermaid diagrams and pictures | Markdown, HTML, Word, PDF |
| **Diagram** | A flowchart, sequence, state or concept diagram, written in Mermaid or SVG | SVG, PNG, PDF, and Mermaid when written in it |
| **Slides** | A deck of up to 60 slides: title, content (with an optional image), two columns, image, chart (bar, line or pie) and quote layouts, with speaker notes and a light or dark theme | PowerPoint, PDF, slide images |
| **Dashboard** | Figures and bar, line or pie charts over up to eight tables the agent fills in, each with when its data was read | CSV, PNG, PDF |
| **Design** | Screens, mockups, landing pages and one-pagers as up to 12 frames of HTML and CSS at fixed sizes, side by side | Frame images, HTML, PDF |
| **Motion** | A short animated explainer or walkthrough: up to 20 timed scenes, two minutes at most, played once in order on a 16:9 stage | MP4 and WebM video, poster image, HTML |

Docs, diagrams, decks, dashboards, designs and motions are drawn on the host into the same sandboxed frame as apps, in the app's colors for light and dark, with no script and nothing loaded from the network. Mermaid is drawn with [Pele](https://pele.run); an SVG keeps only drawing elements, so it cannot run script, follow links or load files. Versions, Compare, Restore, share links, **Open to anyone** and **Publish to the web** work for every kind. **Export** on the desktop downloads the kind's formats; on the phone the card's actions and the artifact's menu hand them to the share sheet.

- **Made on the host:** PDF (every kind, printed by the host's headless browser with nothing reachable on the network; a deck prints one 16:9 slide per page), PowerPoint (written from the deck's source, speaker notes included), Word (written from a doc's Markdown, with the doc's own pictures in it; other images keep their description and only web and mail links stay links) and slide images (one 1920 × 1080 PNG per slide, in a zip), and a diagram's PNG at twice its drawn size. Each is kept with the version it was made from, so exporting the same version again is instant. An export is at most 10 MB.
- **Dashboards:** a dashboard shows "As of" with the newest time its tables were read, so a copy opened later never passes for current. A figure or chart that names a table or column that is not there, or adds up values that are not numbers, fails the preview. A table can be **live** instead: the project's deployments, usage, uptime, threads (title, state, whether done, last active) or pull requests (thread, number, title, state, stage), the agents' work on this host over 30 days (turns, cost and tokens per provider and day), or a CSV (with a header row) or JSON file in the project's folder, such as an export or a metrics file the app writes, of which it shows only the columns it names and which it never writes. A table can also show the records an App artifact in the same project keeps, such as a ledger's spending by category, read again the same way. And it can come from a Shared MCP server approved for the project, such as an analytics service: only a tool the server marks read-only is called, its result filling the table by column name. A table can also read a **plugin's data source**: the Grafana, Amplitude and Salesforce [plugins](plugins.md) provide `grafana` (a data source uid, its query fields such as `expr` for Prometheus or `rawSql` with `format: table` for SQL, and a time range; the first result's columns), `amplitude` (an event, a metric of uniques, totals, share of daily active users or average, how many days back and the interval; `date`, `series` and `value`) and `salesforce` (a SOQL `SELECT`, such as open opportunities by stage; the fields it names, `Account.Name` for a related one), and any other plugin can declare its own. Each reads with the credential saved on the plugin's card in **Settings → Plugins**; a dashboard naming a data source no installed plugin provides says so and opens that page. A dashboard reads a service only after you allow it: the dashboard says which service it reads with **Allow**, and **Stop reading** the service in its menu takes that back. The host reads it again from the dashboard's own project whenever the dashboard is opened (at most every five minutes, or as the dashboard's own refresh rule says, up to once a day; **Refresh** in a live dashboard's toolbar on the desktop changes it as a new version) and stamps "As of" with that read; the published version keeps the tables as they were. A figure over a live table can be **watched**: every ten minutes (or less often, by its refresh rule) the host reads a kept dashboard's live tables again and sends a notification to your devices when that number changes, such as "Used: 40 GB → 55 GB". **Range** in the toolbar of a dashboard with dated tables (a column of dates, or deployments and uptime) shows only the last 7, 30 or 90 days or the last year, counted from when it is drawn, as a new version; figures and charts add up only those rows, "As of" names the range, and tables without dates stay whole. **Export CSV** writes its tables (one after another when there are several, each after its id), with cells a spreadsheet would run as formulas quoted.
- **Outline:** a doc with more than one heading has **Outline** in its toolbar on the desktop, listing its headings by level; choosing one jumps the doc to it.
- **Editing a doc:** **Edit text** in a doc's toolbar on the desktop opens it as formatted text in the same editor as Markdown files (headings, lists, task lists, tables, links and code), with **Edit Markdown** for its source; a doc with footnotes or HTML opens as Markdown, which keeps them. On the phone, its menu opens it as formatted blocks (headings, paragraphs, list items, tasks you tick, quotes), each edited in place with bold, italic, code and link text shown as formatting while you type (their Markdown marks stay, dimmed), and tables and code blocks stay as written, with **Edit Markdown** for the source; **Save** makes a new version marked "Edited by you" with the device it was made on (such as "Edited by you on Ayu's iPhone"), so the agent's next revision builds on your words. If another version arrived while you edited (saved on your other device, or by an agent), saving merges the two when they changed different lines, and the version says "merged with" the one it built on; when both changed the same lines, saving is refused and your text stays open, so nothing is lost. While the same text is open for editing on another of your devices, the editor says which, and where: the heading above where they last typed, or the slide they changed ("Also being edited on MacBook · Goals"). Editing is live: the host keeps one shared copy of the text while anyone edits it, each editor syncs with it about once a second, and words typed elsewhere appear in yours as they are typed, even in the same line, without moving your cursor. The host saves a version once nobody has typed for a minute ("Edited live by you on MacBook and Bo"), merged onto any version an agent saved meanwhile, and the editors' next **Save** builds on that version rather than the one they opened. **Save** saves at once; **Cancel** on the desktop drops what you typed since the last save, unless someone else typed in it too, and closing the editor on the phone keeps it for that quiet-minute save. Lines you did not change keep the Markdown as written, in formatted text on the desktop and in formatted blocks on the phone. A phone paired as a viewer can open your artifacts and, through a link that lets them edit, edit their text. Dashboards and Motions have no editor of their own: their changes come from the agent or a single action such as **Refresh** or **Range**, and they cannot be shared for editing.
- **Pictures in a doc:** a doc's pictures are PNG or JPEG files kept with its version, such as ones `generate_image` made, and shown where its Markdown places them. Formatted text on the desktop shows them while you edit, and every version made from your edits keeps the ones its text still shows.
- **Editing a diagram:** a diagram written in Mermaid has **Edit text** too, on the desktop and the phone: change its labels or lines in the source and **Save**, with the same versions, merging and refusal as a doc. A flowchart also has **Edit labels**, which lists the words on its boxes and arrows so you can change them without the Mermaid syntax; on the desktop the drawing stays in view, and clicking a word on it jumps to that label. Ids, arrows and layout stay as they were. An SVG diagram is changed by asking.
- **Motions on the phone:** **Play as video** in a motion's menu plays the host's MP4 in the phone's own player, kept so it opens instantly the next time.
- **Decks on the phone:** a deck opens one slide at a time; swipe sideways or use the arrows above it. While the same deck is in **Present** on a desktop paired with that host, turning a slide on the phone turns it there too, so the phone works as a remote.
- **Editing a deck:** **Edit text** in a deck's toolbar on the desktop (or its menu on the phone) lists every slide's title, text (or its two columns), quote attribution and speaker notes, with arrows to move a slide up or down; **Save** makes a version marked "Edited by you" with each slide's layout, chart and image kept. A deck's words are live too, as a doc's text is, while its slides keep their order (moving a slide pauses live typing until **Save**). Text edited while another version arrived merges slide by slide and field by field, as a doc's lines do, unless slides were added, removed, moved or relaid out since, or both changed the same lines. A slide whose layout needs a title cannot be saved without one.
- **Editing a design:** **Edit text** in a design's toolbar on the desktop (or its menu on the phone) lists the words in each frame, in order; change them and **Save**, with the same versions and refusal as a doc. The frames' layout and styles stay as they were; ask the agent to change those. A field left empty keeps its words.
- **Designs:** **Make it a project** on a design starts a project whose `design/` folder holds its frames (`frames.html`) and source, and asks the agent to build the screens they show and keep them as the reference for later screens.
- **Design systems:** ask an agent for one in a project and it drafts it from the project's own CSS variables and components. A design can carry tokens (colors, type, corner radius and a spacing unit) and its own fonts as files, which travel with it as data so every artifact drawn with the system shows them offline. **Use as design system** in its menu on the desktop makes it the design system of its project (or of the host, for a design in no project), and a project's own comes before the host's: designs, decks, dashboards and apps previewed after that are drawn with its tokens, unless a design sets its own. **Stop using as design system** goes back to the app's theme. **Restyle with the design system** in a deck's, dashboard's or design's menu draws an existing one again with it, as a new version marked "Restyled with …".
- **Designs (on screen):** each frame shows at its true size, and the canvas scrolls sideways when frames are wider than the screen. A frame's styles reach only that frame. A frame with content past its edges fails the preview, so nothing is cut off in the exported images.
- **Motions:** the toolbar on the desktop plays, pauses and restarts a motion, and its slider scrubs to any moment (the same frame the exported video has there). The scenes play once when it opens, each fading into the next, with CSS animations and no script; with Reduce Motion on, only the first scene shows. The poster image is the opening scene. **Export MP4 video** and **Export WebM video** make the video at 12 frames a second on the host (MP4 needs a browser that can encode H.264, such as Google Chrome; Ramu says so when it cannot): the scenes are stepped to each frame's exact time, so the video matches the timeline however busy the computer is. A scene can have **narration**: words the agent writes, or that you write with **Narration** in the toolbar (**Listen** hears a line first; an empty line removes it; **Save** keeps a new version). The exported video speaks them on this computer, with macOS's own voice or `espeak-ng` on Linux, each starting with its scene and cut at its end, mixed in as AAC (MP4) or Opus (WebM). Nothing leaves the computer. A motion can also have background music, looped under the whole video (quieter under narration), and a sound effect when a scene starts, each an audio file kept with the version, such as one `make_music` or `make_sound` made ([Abilities](agents.md#abilities)); **Sound** in the toolbar sets how loud each plays or removes it, as a new version. A scene's narration can also be recorded in a voice by `speak` on a media account or a speech tool you mapped; that recording plays instead of this computer's voice. A scene can also play a video clip, such as one `make_video` made, behind its words: it starts with the scene, follows play, pause and the slider, fills the frames of the exported video, and its own sound is mixed in until the scene ends.
- **Decks:** a slide whose text does not fit fails the preview, naming the slide, so a published deck has no cut-off text. On the desktop the artifact's toolbar moves between slides and **Present** shows one slide at a time on the whole screen; the arrow keys, Space and Page Up or Down turn slides and Escape stops. While **Edit text** is open the slide controls and **Present** wait until it closes. With a second display connected, **Present** fills that display with the deck and opens **Presenter notes** on this one: the slide's speaker notes, where you are, the time since you started and the next slide's title, following every turn. The app asks once to know your displays.

Records, AI and the other capabilities below are for apps.

## In a thread

**Artifact** on a kept artifact's card (or **Open** in its menu) opens it as a tab beside the thread, with the same toolbar as under **Artifacts**: Edit text, Outline, Range and Refresh, playback, Present and Export. Its back arrow closes the tab.

Each document appears as a card. The card can **Reset**, switch width (Fit, Tablet, Phone), **Expand**, show older **Versions**, keep **Saved scenarios**, and **Export** HTML or source. **Ask about this** adds the document, with its current state, to your next message; **Choose values** attaches only the values you pick.

Each document has one live card: its newest version. When the agent revises it, the older card collapses in place to one row (the title, "v2 · replaced by v4", what the next version changed, and **Go to latest**), so the transcript keeps its order without three similar documents in a row. Expanding an older row shows that version read-only with **Restore**, which publishes it again as the newest version. While the agent checks a revision the live card says **Updating…**; a revision that fails its checks leaves the current version as it was and says why.

A revised card shows **Updated · v4** with the agent's one-line summary of the change, and **Compare** shows the previous and new versions side by side at phone or desktop width, with **Source changes** one click away. Values you entered carry over to the new version when the agent declared that they keep the same meaning (**Undo** puts the new version back to its defaults); otherwise the card lists your earlier values so you can enter them again. The phone follows the same rule, and **Go to latest** scrolls to the live card.

Documents run in an isolated, sandboxed frame with no access to your files or Ramu. They are offline unless the agent declared the exact HTTPS sites they need. On the phone they open in a separate private browser.

## Keeping an artifact

Ask for something to keep ("make me an artifact to split our trip costs") and the agent publishes it as an artifact, or choose **Keep as artifact** on any card. **Artifacts** is on the rail along the sidebar's left edge, with Threads, Inbox, Pull requests and Schedules, and in the phone's tabs: every artifact on the hosts the sidebar's host filter shows on the desktop, each naming its host when there are several, newest first, pinned ones on top, searchable by title. An artifact opens from the host that keeps it. Artifacts is for finding them again, since they come from threads. A project's menu lists its artifacts too. **Make an artifact from this thread** (in a thread's More actions) asks the agent to turn what the thread found or built into an App.

An artifact opens full window on the desktop and full screen on the phone. Its saved values live on the host, so what you enter on the laptop is there on the phone; when two devices change it at once, the later one sees the other's values instead of overwriting them. On the phone, **Add to Home Screen or share** shares a `ramu://artifact/…` link that opens it in Ramu, and **Artifact settings** in its menu renames it, opens it to anyone or closes it again, makes, renews and revokes share links (sent through the share sheet), lists its runs with **Undo run**, and deletes it. The last version opened stays as a **Saved copy** while the host is away, never shown as current.

- **Changing it:** **Ask about this** starts a thread with the artifact attached, and any thread can update an artifact by name. **Edit** lets you point at an element and say what to change; the agent gets that element's screenshot, its text and its markup. **Versions** shows each version's phone and desktop screenshots with what changed, and **Restore** brings one back as the newest.
- **Errors:** a script error on any device is reported to the host with the version and the steps before it. The artifact shows **Fix this**, which starts a thread with that report; the agent reproduces it and publishes a fixed version.
- **Checks that stay:** the checks a version passed run again on every revision, so a change that breaks an existing control is caught before it is published. When an update to Ramu changes the libraries artifacts are built with (React, Chart.js, Dagre), each kept artifact's checks run once against them, and an artifact they would break shows **Fix this** before anyone publishes with them.
- **Duplicate** copies an artifact's code and capabilities with none of its records, values or history. **Import an artifact…** under Artifacts does the same with a share link from another host this desktop is connected to. **Pin**, **Rename** and **Delete artifact** are in its menu; deleting removes its records, photos, runs and share links, and threads keep their cards marked **Artifact deleted**.

## What an artifact may use

An artifact declares what it uses, and the first time it opens it asks once, in plain words, with each item allowed or not. **Artifact settings** shows the same list later, with today's usage, run history and share links. A new version that asks for more asks again for what is new. The artifact never sees a key, a token or another artifact.

- **Records:** named collections of records kept on the host (up to 10,000 records and 20 MB per artifact), checked against the fields the artifact declares. **Export records** downloads them as JSON and CSV; **Import CSV** adds rows. A version that renames or adds fields moves existing records with its declared rules, and its preview fails if records would not fit.
- **AI:** through the providers already signed in on the host, with the model you choose for the artifact (**Fast** is the maintenance model, **Smart** the default model) and a daily request limit. The model sees only what the artifact sends it. Artifact AI shows in **Activity** with the artifact's name, where it can be stopped.
  - **Ask:** one call with no tools, for parsing "coffee 35k yesterday", categorizing or reading a receipt photo, returning text or JSON in the shape the artifact asked for.
  - **Run:** an artifact agent whose only tools are the artifact's records, functions the artifact offers, the HTTPS sites it declared, web search when you allow it, and Shared MCP servers you allow for this artifact one by one (each call asks you first in the artifact, unless you also tick **Run its read-only tools without asking** for that server in **Artifact settings**, which lets tools the server marks read-only run unasked, such as in scheduled runs; any other call still asks). Its steps show in the artifact, **Stop** ends it, deleting records waits for your **Allow**, and **Undo run** in the history puts back every record it changed. An artifact can offer its own runs as toolbar buttons.
  - **Hand off to a thread:** for work that needs code or a new version of the artifact; you confirm the request first.
- **Ask this artifact:** an artifact with records gets a question box ("how much on food in March?") answered from its records by a read-only artifact agent, with a small chart when there is a breakdown. **Keep as a panel** asks a thread to add that answer to the artifact.
- **Photos:** a photo you choose is resized on the device and kept with the artifact; location data is removed.
- **Notifications:** a few a day, on the desktop and as a push on the phone, opening the artifact. Their text reaches the phone through its push service; **Artifacts** in the phone's alert settings turns them off.
- **On its own:** runs on a schedule (hourly, daily or weekly) without the artifact open, and triggers that notify or start a run when a record matches. Schedules run once per period, once after the host was asleep. The host loads the artifact offline to let such runs use its functions. **Schedules** lists every artifact run under **Artifact runs**, on the desktop and the phone.
- **Webhook:** an address in **Artifact settings** where outside services can send records, checked against the artifact's fields and limited in rate.
- **A project folder:** an artifact in a project can read one folder of it, never write.
- **Ramu data:** an artifact can read figures you already see in Ramu, read-only, each source allowed on its own: token use by day and provider (the last 30 days), thread titles and states, and pull requests on threads. Threads and pull requests are the artifact's project's when it has one. Never transcripts, files, credentials or settings.
- **Plugin data:** an artifact can query a plugin's data source (such as Grafana, Amplitude or Salesforce) with the credential saved for the plugin, read-only, the same queries a dashboard's table makes; it declares which and why, the first open asks once, each service has its own box, and **Artifact settings** takes one back. A share link's viewers cannot query them.

On the phone, **Show in the home screen widget** puts an artifact's declared widget (a number or a short list from its records), or a dashboard's first figure with the next few as lines (read live when its tables are), on the iOS or Android home screen; it refreshes when Ramu opens, when the artifact changes and every quarter hour, and says when it was read. An artifact run that keeps working shows as a Live Activity on iOS. Records you add without a connection wait on the phone and are sent in order when the host answers; any the host refuses are listed rather than dropped. A question asked offline waits while the artifact stays open.

## Sharing and shipping

- **Share links** (in **Artifact settings**) open the artifact on any device paired with this host, read-only or able to add records, for a household ledger. Model calls from a link use the artifact's own allowance. Links expire after 30 days unless renewed, and can be revoked. For a doc, a diagram or a deck, **Link that lets them edit** names one person ("Bo"): opened on a device paired with this host, it lets them edit the text as you would on the phone, their saves merge with yours line by line, each version says "Edited by Bo", and the editor shows when you are both editing.
- **Publish to the web** deploys the artifact's exact tested HTML as a static site on your own account: GitHub Pages through the GitHub login in Settings, Netlify, Vercel or Cloudflare Pages through the account connected in **Settings → Deploy** ([Deploying an app](deploy.md#connect-an-account)), the same one deploys use. Choosing the platform and pressing **Publish** is the approval. The artifact shows its address, and when a newer version exists, **Update live site** deploys it to the same site. An artifact with records or AI cannot go on the web as it is; the menu offers **Make it a project** instead.
- **Open to anyone** (in **Artifact settings**) shows the artifact to people without Ramu while this host is on: it gets an address of its own through the host's Cloudflare (`cloudflared`) or ngrok tool and serves only that artifact, read-only. Only an artifact that uses no records, AI or other host feature can be opened; **Close to everyone** ends it, and open artifacts open again after a restart.
- **Tell people what shipped** in a project's menu (when it has a repository) opens New chat with a request already typed: **Make a release note** asks for a Doc and **Make a launch deck** for Slides, both from the pull requests merged since the last release. Change the request before sending if you want.
- **Make it a project** (artifact menu, on the desktop and the phone) writes the artifact's sources, record fields (`data/schema.json`) and records (`data/seed.json`) to a folder, in one of two places:
  - **Into a project:** a folder inside one of the host's projects (the artifact's own project first), named after the artifact or a path you type such as `src/pricing`. A thread starts in that project to build it in, unless you untick **Start a thread there**; the project list stays as it is.
  - **New project:** a new folder named after the artifact (or the name you type), beside your other repositories unless **Change…** opens the host's folder browser to put it elsewhere. The folder joins your projects and a thread starts there to turn it into an app that builds and runs.

  A folder that already holds files is never written into: Ramu uses the next numbered name (`pricing-2`) instead.

## For agents

Agents use `artifact_preview` to test a document (one HTML file or a small project, up to 512 KB) and `artifact_publish` to publish the exact tested version. A doc (`kind: "doc"`, Markdown in `source`, up to 200 KB) or a diagram (`kind: "diagram"`, `format` `mermaid` or `svg`, the text in `source`) is previewed the same way and has its own checks: a diagram must parse, and every heading of a doc must have an anchor of its own (no empty headings, no two with the same name, and every `#link` reaches one). Preview clicks the declared controls in a headless browser, takes screenshots at phone and desktop widths, and blocks publication on script errors or failed checks. A revision passes `previous` to both and a short `changes` sentence to publish; checks kept with the previous version run again unless dropped on purpose.

- `artifact_publish` with `artifact: true` keeps a new document as an artifact (with `title` and one emoji `icon`); `artifact: "<id>"` publishes a new version of an existing artifact from any thread.
- `artifact_list` and `artifact_get` find an artifact and read its kind, sources, capabilities and last error; `artifact_records` queries, adds or updates its records; `artifact_run` starts one of its runs; `artifact_published` records where it is live. `artifact_read` and `artifact_versions` read a thread's own documents.
- Capabilities are declared in `ramu.json` or a `<meta name="ramu-capabilities">` tag and used through `window.ramuContent`: `records`, `ai.ask`, `ai.run`, `ai.tool`, `ai.image`, `pickImage`, `files`, `notify`, `folder`, `ramu`, `services` and `startThread`. `ai.image(prompt)` returns a picture as a data URL, made by a signed-in provider with image generation through the same routing as threads use ([Abilities](agents.md#abilities)), counted against the artifact's daily AI budget; the AI grant is the approval, and only the prompt is sent. Preview answers these from an in-frame fake so checks can exercise them.
- Pinned libraries: React 19.3.0, Chart.js 4.6.1, Dagre 2.0.4.
- `<link rel="stylesheet" href="ramu:kit">` adds app-styled cards, buttons, badges, tables and tabs; `<svg data-icon="name">` inserts a [Lucide](https://lucide.dev) icon. Both work offline.
- Theme variables (`--background`, `--foreground`, `--primary`, `--surface`, `--border`, `--chart-1` to `--chart-6` and more) follow the app's colors and light or dark mode.
- `window.ramuContent.setState()` and `onRestore()` keep custom state between views; on a kept artifact, that state is shared through the host.
