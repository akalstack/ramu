# Artifacts

Agents can publish small interactive documents in a thread, such as explanations, diagrams, data explorers, calculators and prototypes. Their controls run locally with no further model call. A document you keep becomes an **artifact**: listed under **Artifacts** on the desktop and the phone, opened without its thread, changed by asking in any thread, and able to keep records and use your host's AI when you allow it.

For a quick choice, a short form or a status summary used once in the conversation, the agent shows a [card](working-with-agents.md#cards-in-a-thread) instead, drawn with the app's own controls.

## Kinds

The agent picks the kind from what you ask for. It shows as a mark on the artifact's row and card, and **Artifacts** on the desktop filters by it.

| Kind | What it is | Exports |
| --- | --- | --- |
| **App** | Interactive web content: calculators, trackers, explorers, games | HTML, source, PDF |
| **Doc** | Writing to keep, such as a report, plan, spec or notes, in Markdown with tables, task lists, footnotes, Mermaid diagrams and pictures | Markdown, HTML, Word, PDF |
| **Diagram** | A flowchart, sequence, state or concept diagram, in Mermaid or SVG | SVG, PNG, PDF, and Mermaid when written in it |
| **Slides** | A deck of up to 60 slides: title, content (with an optional image), two columns, image, chart (bar, line or pie) and quote layouts, with speaker notes and a light or dark theme | PowerPoint, PDF, slide images |
| **Dashboard** | Figures and bar, line or pie charts over up to eight tables the agent fills in, each with when its data was read | CSV, PNG, PDF |
| **Design** | Screens, mockups, landing pages and one-pagers as up to 12 frames of HTML and CSS at fixed sizes, side by side | Frame images, HTML, PDF |
| **Motion** | A short animated explainer or walkthrough: up to 20 timed scenes, two minutes at most, played once in order on a 16:9 stage | MP4 and WebM video, poster image, HTML |
| **Card** | A small tool that adds, shows and totals entries, such as a tracker, log, checklist or sign-up list, drawn with the app's own controls | PDF |

A **Card** opens without a frame: the desktop and the phone draw it with their own buttons, fields and lists, in your theme and language, so it opens instantly and works like the rest of the app. Its buttons save entries to its records and remove them straight away, with no model call. What you type stays on the device as a draft until you save it, and a saved entry clears the form. A card asks once to keep records, like an app. The host also draws a card as a page, used for its preview, Versions, PDF, **Publish to the web** and **Open to anyone**, where its controls show their starting values. **Keep as artifact** on a [card in a thread](working-with-agents.md#cards-in-a-thread) asks the agent to make it a Card artifact that keeps what it collects.

The host draws the other kinds into the same sandboxed frame as apps, in the app's light and dark colors, with no script or network. Mermaid is drawn with [Pele](https://pele.run). An SVG keeps only drawing elements, so it can't run script, follow links or load files. Versions, Compare, Restore, share links, **Open to anyone** and **Publish to the web** work for every kind. **Export** on the desktop downloads the kind's formats. On the phone, the card's actions and the artifact's menu hand them to the share sheet.

- **Made on the host:** PDF (every kind, printed by the host's headless browser with no network access, one 16:9 slide per page for a deck), PowerPoint (from the deck's source, speaker notes included), Word (from a doc's Markdown, with the doc's own pictures in it. Other images keep their description, and only web and mail links stay links), slide images (one 1920 × 1080 PNG per slide, in a zip) and a diagram's PNG at twice its drawn size. Exports are kept with their version, so a repeat export is instant. An export is at most 10 MB.
- **Dashboards:** "As of" shows the newest time its tables were read, so a copy opened later never passes for current. A figure or chart that names a missing table or column, or sums values that aren't numbers, fails the preview.
  - A table can be **live**, reading the project's uptime checks, threads (title, state, whether done, last active), pull requests (thread, number, title, state, stage), the agents' work on this host over 30 days (turns, cost and tokens per provider and day), or a CSV (with a header row) or JSON file in the project's folder, such as a metrics file the app writes (only the columns it names, never written). It can also read the records an App artifact in the same project keeps, such as a ledger's spending by category, or a read-only tool of a Shared MCP server approved for the project, such as an analytics service, whose result fills the table by column name.
  - A table can read a **plugin's data source**. The Grafana, Amplitude and Salesforce [plugins](plugins.md) provide `grafana` (a data source uid, its query fields such as `expr` for Prometheus or `rawSql` with `format: table` for SQL, and a time range, giving the first result's columns), `amplitude` (an event, a metric of uniques, totals, share of daily active users or average, how many days back and the interval, giving `date`, `series` and `value`) and `salesforce` (a SOQL `SELECT`, such as open opportunities by stage, giving the fields it names, `Account.Name` for a related one). Any plugin can declare its own. Each reads with the credential saved on the plugin's card in **Customize → Plugins**. A dashboard naming a data source no installed plugin provides says so and opens that page.
  - A dashboard reads a service only after you press **Allow** on it, and **Stop reading** in its menu takes that back. The host reads again from the dashboard's project when it's opened, at most every five minutes, or as its refresh rule says, up to once a day. **Refresh** in the desktop toolbar changes that rule as a new version. The published version keeps the tables as they were.
  - A figure over a live table can be **watched**. Every ten minutes (or less often, by its refresh rule) the host rereads a kept dashboard's live tables and notifies your devices when the number changes, such as "Used: 40 GB → 55 GB".
  - **Range** in the toolbar of a dashboard with dated tables (a column of dates, or deployments and uptime) shows only the last 7, 30 or 90 days or the last year, as a new version. Figures and charts sum only those rows, "As of" names the range, and tables without dates stay whole.
  - **Export CSV** writes its tables (one after another when there are several, each after its id), quoting cells a spreadsheet would run as formulas.
- **Outline:** on the desktop, a doc with more than one heading has **Outline** in its toolbar, listing headings by level to jump to.
- **Editing a doc:** **Edit text** in a doc's toolbar on the desktop opens it as formatted text in the Markdown file editor (headings, lists, task lists, tables, links and code). A doc with footnotes or HTML opens as Markdown, which keeps them. On the phone, its menu opens it as formatted blocks (headings, paragraphs, list items, tasks you tick, quotes) edited in place, with bold, italic, code and links shown as formatting and their Markdown marks dimmed. Tables and code blocks stay as written. **Edit Markdown** opens the source on both.
  - **Save** makes a new version marked "Edited by you" with the device it was made on (such as "Edited by you on Ayu's iPhone"), so the agent's next revision builds on your words. If another version arrived meanwhile (from your other device or an agent), saving merges the two when they changed different lines, and the version says "merged with" the one it built on. When both changed the same lines, saving is refused and your text stays open. Lines you didn't change keep their Markdown as written.
  - Editing is live. While the same text is open on another of your devices, the editor says which and where ("Also being edited on MacBook · Goals", the heading above where they last typed or the slide they changed). The host keeps one shared copy, each editor syncs with it about once a second, and words typed elsewhere appear as they're typed, even in the same line, without moving your cursor. Once nobody has typed for a minute the host saves a version ("Edited live by you on MacBook and Bo"), merged onto any version an agent saved meanwhile, and the next **Save** builds on it. **Save** saves at once. **Cancel** on the desktop drops what you typed since the last save, unless someone else typed in it too. Closing the editor on the phone keeps your text for the quiet-minute save.
  - A phone paired as a viewer can open your artifacts, and edit their text through a link that lets them edit. Dashboards and Motions have no editor. They change through the agent or an action such as **Refresh** or **Range**, and can't be shared for editing.
- **Pictures in a doc:** PNG or JPEG files kept with the version, such as ones `generate_image` made, shown where the Markdown places them. Formatted text on the desktop shows them while you edit, and your edited versions keep the ones the text still shows.
- **Editing a diagram:** a Mermaid diagram has **Edit text** too, on the desktop and the phone, with the same versions, merging and refusal as a doc. A flowchart also has **Edit labels**, listing the words on its boxes and arrows to change without Mermaid syntax. On the desktop the drawing stays in view, and clicking a word jumps to its label. Ids, arrows and layout stay as they were. An SVG diagram changes only by asking.
- **Motions on the phone:** **Play as video** in a motion's menu plays the host's MP4 in the phone's own player, kept so it opens instantly next time.
- **Decks on the phone:** one slide at a time. Swipe sideways or use the arrows above it.
- **Editing a deck:** **Edit text** in a deck's toolbar on the desktop (or its menu on the phone) lists every slide's title, text (or its two columns), quote attribution and speaker notes, with arrows to move a slide. **Save** makes a version marked "Edited by you", keeping each slide's layout, chart and image. Editing is live as in a doc (moving a slide pauses it until **Save**). Edits merge with another version slide by slide and field by field, unless slides were added, removed, moved or relaid out, or both changed the same lines. A slide whose layout needs a title can't be saved without one.
- **Editing a design:** **Edit text** in a design's toolbar on the desktop (or its menu on the phone) lists the words in each frame, in order, saved with the same versions and refusal as a doc. Layout and styles stay, so ask the agent to change those. A field left empty keeps its words.
- **Designs:** **Make it a project** on a design starts a project whose `design/` folder holds its frames (`frames.html`) and source, and asks the agent to build the screens they show and keep them as the reference for later screens.
- **Design systems:** ask an agent for one in a project and it drafts it from the project's CSS variables and components. A design can carry tokens (colors, type, corner radius and a spacing unit) and font files, so every artifact drawn with the system shows them offline. **Use as design system** in its menu on the desktop makes it the design system of its project (or of the host, for a design in no project), and a project's comes before the host's. Designs, decks, dashboards and apps previewed after that use its tokens, unless a design sets its own. **Stop using as design system** goes back to the app's theme. **Restyle with the design system** in a deck's, dashboard's or design's menu redraws an existing one with it, as a new version marked "Restyled with …".
- **Designs (on screen):** each frame shows at its true size, and the canvas scrolls sideways when frames are wider than the screen. A frame's styles reach only that frame. A frame with content past its edges fails the preview, so nothing is cut off in the exported images.
- **Motions:** the desktop toolbar plays, pauses and restarts a motion, and its slider scrubs to any moment (the same frame the exported video has there). The scenes play once when it opens, each fading into the next, with CSS animations and no script. With Reduce Motion on, only the first scene shows. The poster image is the opening scene.
  - **Export MP4 video** and **Export WebM video** render on the host at 12 frames a second. MP4 needs a browser that can encode H.264, such as Google Chrome, and Ramu says so when it can't. Each frame is stepped to its exact time, so the video matches the timeline however busy the computer is.
  - A scene can have **narration**: words the agent writes, or that you write with **Narration** in the toolbar (**Listen** plays a line first, an empty line removes it, **Save** keeps a new version). The exported video speaks them with macOS's own voice or `espeak-ng` on Linux, each starting with its scene and cut at its end, mixed in as AAC (MP4) or Opus (WebM). Nothing leaves the computer. A narration recorded by `speak` on a media account or a speech tool you mapped plays instead of that voice.
  - A motion can have background music, looped under the whole video (quieter under narration), and a sound effect when a scene starts. Each is an audio file kept with the version, such as one `make_music` or `make_sound` made ([Abilities](working-with-agents.md#abilities)). **Sound** in the toolbar sets how loud each plays or removes it, as a new version.
  - A scene can play a video clip behind its words, such as one `make_video` made. It starts with the scene, follows play, pause and the slider, fills the exported video's frames, and its own sound is mixed in until the scene ends.
- **Decks:** a slide whose text doesn't fit fails the preview, naming the slide, so a published deck has no cut-off text. On the desktop the toolbar moves between slides; it waits while **Edit text** is open. To present a deck, export it as PowerPoint or PDF and use the app you present with.

Records are for apps and cards. AI and the other capabilities below are for apps.

## In a thread

Each document appears as a card. The card can **Reset**, switch width (Fit, Tablet, Phone), **Expand**, show older **Versions**, keep **Saved scenarios**, and **Export** HTML or source. **Ask about this** adds the document, with its current state, to your next message. **Choose values** attaches only the values you pick. **Artifact** on a kept artifact's card (or **Open** in its menu) opens it as a tab beside the thread, with the same toolbar as under **Artifacts**. Its back arrow closes the tab.

Only the newest version's card is live. When the agent revises it, the older card collapses in place to one row (the title, "v2 · replaced by v4", what changed, and **Go to latest**). Expanding it shows that version read-only with **Restore**, which publishes it again as the newest. While the agent checks a revision, the live card says **Updating…**, and a revision that fails its checks leaves the current version alone and says why.

A revised card shows **Updated · v4** with the agent's one-line summary. **Compare** shows both versions side by side at phone or desktop width, with **Source changes** one click away. Values you entered carry over when the agent declared they keep the same meaning (**Undo** resets the new version to its defaults). Otherwise the card lists your earlier values to enter again. The phone works the same.

Documents run in an isolated, sandboxed frame with no access to your files or Ramu. They're offline unless the agent declared the exact HTTPS sites they need. On the phone they open in a separate private browser.

## Keeping an artifact

Ask for something to keep ("make me an artifact to split our trip costs") and the agent publishes it as an artifact, or choose **Keep as artifact** on any card. **Make an artifact from this thread** (in a thread's More actions) asks the agent to turn what the thread found or built into an App.

**Artifacts** is on the rail along the sidebar's left edge and in the phone's tabs. It lists every artifact on the hosts the sidebar's host filter shows, naming each one's host when there are several, newest first, pinned ones on top, searchable by title. A project's menu lists its artifacts too. An artifact opens from the host that keeps it, full window on the desktop and full screen on the phone.

Saved values live on the host, so what you enter on the laptop is there on the phone. When two devices change it at once, the later one sees the other's values instead of overwriting them. The last version opened stays as a **Saved copy** while the host is away, never shown as current.

**Install as app** in an artifact's menu on the desktop adds it to this computer's apps, with its title and emoji as its name and icon: under **Applications › Ramu Apps** (and Launchpad) on macOS, in the Start menu under **Ramu Apps** on Windows, and in the applications menu on Linux. Opening it shows that artifact alone in a window of its own, always at its newest version, with its records, AI and live updates as in Ramu, and Ramu's main window stays hidden until you open Ramu itself. A thread the artifact starts opens in Ramu's main window. On Windows the window has its own taskbar button and icon; on macOS the Dock shows Ramu's icon while it's open. **App icon…** in the same menu gives the app a picture instead of the emoji: **Choose picture…** crops one of yours to a square, and **Make with AI** asks the image generation chosen in Settings → Models → Abilities for one from the artifact's name, or from a few words you type. **Use emoji** goes back. The picture is kept with the artifact on its host, so every desktop that installs it shows the same icon. Renaming the artifact, changing its emoji or setting a picture updates the installed app the next time the artifact is shown, and **Uninstall app** removes it. **Open in its own window** opens the same window without installing anything. Nothing is published: the app opens from your host as the artifact does in Ramu.

On the phone, **Add to Home Screen or share** shares a `ramu://artifact/…` link that opens it in Ramu. **Artifact settings** in its menu renames it, opens it to anyone or closes it again, makes, renews and revokes share links (sent through the share sheet), lists its runs with **Undo run**, and deletes it.

- **Changing it:** **Ask about this** starts a thread with the artifact attached, and any thread can update an artifact by name. **Edit** lets you point at an element and say what to change, and the agent gets its screenshot, text and markup. **Versions** shows each version's phone and desktop screenshots with what changed, and **Restore** brings one back as the newest.
- **Errors:** a script error on any device reaches the host with the version and the steps before it. **Fix this** on the artifact starts a thread where the agent reproduces it and publishes a fix.
- **Checks that stay:** the checks a version passed run again on every revision, so a change that breaks an existing control is caught before publishing. When a Ramu update changes the artifact libraries (React, Chart.js, Dagre), each kept artifact's checks run once against them, and one they would break shows **Fix this**.
- **Duplicate** copies an artifact's code and capabilities without its records, values or history. **Import an artifact…** under Artifacts does the same with a share link from another host this desktop is connected to. **Pin**, **Rename** and **Delete artifact** are in its menu. Deleting removes its records, photos, runs and share links, and threads keep their cards marked **Artifact deleted**.

## What an artifact may use

An artifact declares what it uses and asks once in plain words the first time it opens, item by item. **Artifact settings** shows the same list later, with today's usage, run history and share links. A new version asks again only for what's new. The artifact never sees a key, a token or another artifact.

- **Records:** named collections kept on the host (up to 10,000 records and 20 MB per artifact), checked against the fields the artifact declares. **Export records** downloads them as JSON and CSV, and **Import CSV** adds rows. A version that renames or adds fields moves existing records with its declared rules, and its preview fails if records wouldn't fit.
- **AI:** through the providers already signed in on the host, with the model you choose for the artifact (**Fast** is the maintenance model, **Smart** the default model) and a daily request limit. The model sees only what the artifact sends. Artifact AI shows in **Activity** with the artifact's name, where you can stop it.
  - **Ask:** one call with no tools, for parsing "coffee 35k yesterday", categorizing or reading a receipt photo. It returns text or JSON in the shape the artifact asked for.
  - **Run:** an artifact agent whose only tools are the artifact's records, functions the artifact offers, the HTTPS sites it declared, web search when you allow it, and Shared MCP servers you allow for this artifact one by one. Each MCP call asks you first, unless you tick **Run its read-only tools without asking** for that server in **Artifact settings**, which lets tools the server marks read-only run unasked (in scheduled runs, say). Its steps show in the artifact, **Stop** ends it, deleting records waits for your **Allow**, and **Undo run** in the history puts back every record it changed. An artifact can offer its own runs as toolbar buttons.
  - **Hand off to a thread:** for work that needs code or a new version of the artifact. You confirm the request first.
- **Ask this artifact:** an artifact with records gets a question box ("how much on food in March?") answered from its records by a read-only artifact agent, with a small chart when there's a breakdown. **Keep as a panel** asks a thread to add that answer to the artifact.
- **Photos:** a photo you choose is resized on the device and kept with the artifact, with location data removed.
- **Notifications:** a few a day, on the desktop and as a phone push (its text goes through the push service), opening the artifact. **Artifacts** in the phone's alert settings turns them off.
- **On its own:** scheduled runs (hourly, daily or weekly) without the artifact open, and triggers that notify or start a run when a record matches. Each runs once per period, and once after the host slept. The host loads the artifact offline so these runs can use its functions. **Schedules** lists every artifact run under **Artifact runs**, on the desktop and the phone.
- **Webhook:** an address in **Artifact settings** where outside services can send records, checked against the artifact's fields and rate limited.
- **A project folder:** an artifact in a project can read one folder of it, never write.
- **Ramu data:** read-only figures you already see in Ramu, each source allowed on its own: token use by day and provider (the last 30 days), thread titles and states, and pull requests on threads. Threads and pull requests are the artifact's project's when it has one. Never transcripts, files, credentials or settings.
- **Plugin data:** read-only queries to a plugin's data source (such as Grafana, Amplitude or Salesforce) with the plugin's saved credential, the same queries a dashboard table makes. The artifact declares which and why, you allow each service once, and **Artifact settings** takes one back. A share link's viewers can't query them.

On the phone, **Show in the home screen widget** puts an artifact's declared widget (a number or a short list from its records), or a dashboard's first figure with the next few as lines (read live when its tables are), on the iOS or Android home screen. It refreshes when Ramu opens, when the artifact changes and every 15 minutes, and says when it was read. An artifact run that keeps working shows as a Live Activity on iOS. Records you add offline wait on the phone and go in order when the host answers, and any it refuses are listed, not dropped. A question asked offline waits while the artifact stays open.

## Sharing and shipping

- **Share links** (in **Artifact settings**) open the artifact on any device paired with this host, read-only or able to add records, for a household ledger say. Model calls from a link use the artifact's own allowance. Links expire after 30 days unless renewed, and can be revoked. For a doc, a diagram or a deck, **Link that lets them edit** names one person ("Bo"). On a device paired with this host, they edit the text as you would on the phone, their saves merge with yours line by line, and each version says "Edited by Bo".
- **Publish to the web** deploys the artifact's exact tested HTML as a static site on GitHub Pages, in a public repository on your own account, through the GitHub login in Settings. Pressing **Publish** is the approval. The artifact shows its address, and **Update live site** deploys a newer version there. An artifact with records or AI can't go on the web as it is, so the menu offers **Make it a project** instead.
- **Open to anyone** (in **Artifact settings**) shows the artifact to people without Ramu while this host is on. It gets its own address through the host's Cloudflare (`cloudflared`) or ngrok tool and serves only that artifact, read-only. Only an artifact that uses no records, AI or other host feature can be opened. **Close to everyone** ends it, and open artifacts open again after a restart.
- **Tell people what shipped** in a project's menu (when it has a repository) opens New chat with a request already typed. **Make a release note** asks for a Doc and **Make a launch deck** for Slides, both from the pull requests merged since the last release.
- **3D models** (`.glb` and `.gltf`) open in a viewer that orbits the model under neutral lights and shows its triangle count and size, with a menu of a rigged model's animations. It opens from a `make_model` row's attachment or the files viewer, and on the phone from the row.
- **Make it a project** (artifact menu, on the desktop and the phone) writes the artifact's sources, record fields (`data/schema.json`) and records (`data/seed.json`) to a folder, in one of two places:
  - **Into a project:** a folder inside one of the host's projects (the artifact's own project first), named after the artifact or a path you type such as `src/pricing`. A thread starts in that project to build it, unless you untick **Start a thread there**. The project list stays as it is.
  - **New project:** a new folder named after the artifact (or the name you type), beside your other repositories unless **Change…** opens the host's folder browser to put it elsewhere. The folder joins your projects and a thread starts there to turn it into an app that builds and runs.

  Ramu never writes into a folder that already holds files. It uses the next numbered name (`pricing-2`) instead.

## For agents

Agents use `artifact_preview` to test a document (one HTML file or a small project, up to 512 KB) and `artifact_publish` to publish the exact tested version. A doc (`kind: "doc"`, Markdown in `source`, up to 200 KB) or a diagram (`kind: "diagram"`, `format` `mermaid` or `svg`, the text in `source`) is previewed the same way, with its own checks. A diagram must parse, and every heading of a doc must have its own anchor (no empty headings, no two with the same name, and every `#link` reaches one). Preview clicks the declared controls in a headless browser, screenshots phone and desktop widths, and blocks publishing on script errors or failed checks. A revision passes `previous` to both and a short `changes` sentence to publish. Checks kept with the previous version run again unless dropped on purpose.

- `artifact_publish` with `artifact: true` keeps a new document as an artifact (with `title` and one emoji `icon`). `artifact: "<id>"` publishes a new version of an existing artifact from any thread.
- A card (`kind: "card"`) is [A2UI](https://a2ui.org) v1.0 messages in `messages`, building one surface with the same parts as a [card in a thread](working-with-agents.md#cards-in-a-thread), and its collections in `records` (`{"expenses":{"fields":{"amount":"number","note":"string?"}}}`). Each collection is read at `/records/<collection>`, newest first, with each record's `id` and `createdAt`. Buttons save with `addRecord` (`collection` and `values`) and remove with `deleteRecord` (`collection` and `id`), and `sum` and `count` total a collection. A card's buttons can't send events, since no agent answers them.
- `artifact_list` and `artifact_get` find an artifact and read its kind, sources, capabilities and last error. `artifact_records` queries, adds or updates its records, `artifact_run` starts one of its runs, and `artifact_published` records where it's live. `artifact_read` and `artifact_versions` read a thread's own documents.
- Capabilities are declared in `ramu.json` or a `<meta name="ramu-capabilities">` tag and used through `window.ramuContent`: `records`, `ai.ask`, `ai.run`, `ai.tool`, `ai.image`, `pickImage`, `files`, `notify`, `folder`, `ramu`, `services` and `startThread`. `ai.image(prompt)` returns a picture as a data URL, made by a signed-in provider with image generation through the same routing threads use ([Abilities](working-with-agents.md#abilities)), and counts against the artifact's daily AI budget. The AI grant is the approval, and only the prompt is sent. Preview answers these from an in-frame fake so checks can exercise them.
- Pinned libraries, all offline: React 19.3.0, Chart.js 4.6.1, Dagre 2.0.4, three.js 0.186.1 with its GLTFLoader, OrbitControls and SkeletonUtils.
- **Games and 3D:** models, textures and sounds (`glb`, `gltf`, `bin`, `ktx2`, `png`, `jpg`, `webp`, `mp3`, `ogg`, `wav`) are assets. A file names the attachment `make_model`, `generate_image`, `make_music` or `make_sound` made. Assets are kept with the version outside the 512 KB source limit, up to 25 MB each and 50 MB together. Code reaches one with `import fox from './models/fox.glb'` or `ramuAsset('models/fox.glb')` (a URL), and an `<img>` or `<audio>` naming it works as written. A revision keeps an asset by naming its path with no content. Preview runs WebGL in software, and a 3D canvas that stays one color after the page loads fails it, as clipped text does. A clicked artifact gets the keyboard, and its frame allows fullscreen and gamepads. The guide asks for on-screen touch controls whenever a game uses keys. **Publish to the web** and **Make it a project** carry the assets.
- `<link rel="stylesheet" href="ramu:kit">` adds app-styled cards, buttons, badges, tables and tabs, and `<svg data-icon="name">` inserts a [Lucide](https://lucide.dev) icon. Both work offline.
- Theme variables (`--background`, `--foreground`, `--primary`, `--surface`, `--border`, `--chart-1` to `--chart-6` and more) follow the app's colors and light or dark mode.
- `window.ramuContent.setState()` and `onRestore()` keep custom state between views. On a kept artifact, that state is shared through the host.
