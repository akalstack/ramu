# Ramu vs T3 Code v0.1.0

Compared on 2026-10-16 using the [T3 Code v0.1.0 release notes](https://github.com/pingdotgg/t3code/releases/tag/v0.1.0), Ramu's README and `docs/UI.md`, and a keyword grep of `apps/web/src`. Ramu's code was not inspected in depth, so treat "already has" items as unverified until checked.

**Verdict:** roughly even, with different strengths.

## Where Ramu is still ahead
- Automatic provider fallback across usage limits, resuming after a restart.
- Persistent goals across provider changes.
- Shared memory and learning (skills, lessons, "What Ramu learned" summary).
- Advisors and helpers.
- Integrated editor, terminals, Git and review with selective undo.
- English and Bahasa Indonesia.

## Where T3 is ahead
- Provider breadth: Pi, Muse Code, OpenCode 2, and the ACP Registry (Devin, Cline, Kimi, Droid and others).
- An MCP that lets agents drive the app (threads, forks, merges, PRs, schedules, previews), plus OAuth for outside agents. Agents cannot approve their own permission requests.
- Subagent lineage, forking from any finished run, and merge-back.
- Scheduled tasks with webhook triggers.
- PR watches that wake the agent on checks, reviews or conflicts.
- Mobile: native PR review, iPad layout, LAN and tailnet discovery.
- Signed releases.

## Ramu already has (per grep)
Context meter, find in thread, minimap, reopen closed tabs, grouped command palette.

## Ramu is missing
Mermaid rendering, parent-thread breadcrumb, onboarding wizard, drag-to-reorder right-panel tabs.

## Transport used by T3 for chat
- Claude: most likely the Claude Agent SDK (`providers.md`: "Claude's SDK mode emits no goal events").
- Codex: most likely the native app-server over JSON-RPC (`packages/effect-codex-app-server`).
- ACP is used for the registry providers (`provider-acp`, `provider-acp-registry`, `effect-acp`), not for Claude or Codex.
- Cursor uses the official SDK; Pi runs in RPC mode.
- Not confirmed from source: the adapters likely live in `apps/server/src/orchestration-v2/Adapters/`.

## Suggested build order
1. ACP registry support.
2. Agent board plus subagent lineage and breadcrumb.
3. Thread fork and merge-back.
4. PR watch that wakes the agent.
5. Usage and cost page.
6. A Ramu MCP (agents must not approve their own permissions).
7. Signed builds and LSP.

## Suggested UI order (keep Ramu's design)
1. Quick wins: Mermaid, pinned scrolling, composer banner fixes, pending requests wait until typing stops.
2. Breadcrumb and lineage, together with the agent board.
3. Draggable right-panel tabs and resizing in one frame.
4. PR comment filters, then guided review.
5. Onboarding wizard that follows custom themes.
6. Mobile PR review.

## UI ideas from T3
- Chat and composer: Mermaid in code blocks; breadcrumb and lineage; stay pinned when toggling tools or thinking; banner actions inline when they fit; steer-vs-queue setting with Cmd/Ctrl+Enter inverting it; throttled Thinking shimmer; details-panel shortcut.
- Panels: drag-reorder right-panel tabs; resize commits in one frame; maximized panel stays maximized; panel toggles don't re-render timeline or composer.
- Review and PRs: PR comment filters (bots, resolved), guided review, in-place confirmation, file tree scaling with font size.
- Settings and theming: per-project provider toggles; synced model favorites, renameable built-in models; Cmd/Ctrl+F focuses settings search; always-visible focus borders, nested radii, tooltips clear of traffic lights, no lingering popovers.
- Mobile: native PR review (offline), waiting thread status, saved list filters, iPad layout.

Keep Ramu's identity: the integrated workspace plus fallback, goals and memory. Surface fallback state, goal progress and the learning summary in the UI, since T3 has no equivalent.
