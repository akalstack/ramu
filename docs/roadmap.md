# Roadmap

Unfinished work only. Completed items are removed; lasting behavior lives in the [guide](README.md#guide). Open an issue before starting anything here.

Every item needs scoped tests and typechecks for the packages it touches. Desktop-facing changes also run `pnpm build` then `pnpm test:desktop-smoke` ([contributing](../CONTRIBUTING.md#checks)). Checks that need a physical phone, a signed build, a live provider or a second host are listed under [Acceptance](#acceptance) and stay open until run; fake-provider tests do not close them.

## Release

- macOS signing and notarization in CI, and signed auto-update. The Apple Developer account is in place; the release workflow signs once the repository has the Developer ID certificate and App Store Connect API key secrets listed in [Releasing](contributing/releasing.md#signing-and-packaged-checks). Turn on `APP_AUTO_UPDATE` in `packages/shared/src/updates.ts` after a signed build installs on a second Mac.
- Linux: the first release run builds x64 and arm64 `.deb`, `.rpm` and AppImage. Install the `.rpm` on Fedora and start the AppImage on Ubuntu 24.04 (its AppArmor user-namespace limit can block Electron's sandbox) by hand; only the `.deb` is smoke-tested in CI.
- Windows: the port is under way on the `windows-port` branch (CI on Windows, the local service over a named pipe). Next are the server's shell, terminal and path handling, packaging, and a hands-on run in a Windows 11 VM.
- Mobile distribution: the Expo project, app ID `com.akalstack.ramu` and Android push (FCM) are set up. EAS holds the Android upload keystore and the Play submission key (`play-submit@akalstack-ramu`). Remaining: upload the first production `.aab` to Play's internal track by hand (later releases use `eas:release:android`), and on the Apple side an APNs key for iOS push and the first build to TestFlight.

## Implementation

- **Transport:** bounded replay and snapshot recovery for every resource, and defined connection outcomes (current, synchronizing, disconnected, authorization rejected, outcome unknown) that keep drafts and queued messages; mutations that cannot be retried report an unknown outcome and reconcile. Start from measurements on real networks ([Architecture](contributing/architecture.md#transport)).
- **Background terminals:** the owner of Cursor's native background commands, checked on a live turn as Claude's, Codex's and OpenCode's were ([Architecture](contributing/architecture.md#providers)); it needs a paid Cursor login, since Cursor's SDK refuses free accounts (`plan_required`, tried on 2026-11-15). The ACP client-terminal boundary stays off until a runtime uses it; Antigravity 1.4.3 does not.
- **Mobile:** IME composition checks on a device. Add a phone entry for a desktop setting only when it clearly helps someone away from the laptop.
- **Thread titles:** OpenCode 2.2.7 names a session from its first prompt (`session.renamed`, checked live on 2026-11-15) and Ramu uses that title. Codex 0.167.2 generates titles only in its terminal UI, so app-server sends no `thread/name/updated` unless a client names the thread, and Antigravity 1.4.3 sent no ACP `session_info_update` title (2026-11-09); Ramu writes those titles itself. Recheck Codex with a live turn that completes (the 2026-11-15 one hit the account's usage limit).
- **Test device video on the phone through a tunnel:** when WebRTC cannot connect (a phone reaching the host through a tunnel that blocks UDP), the phone would play Simlock's stream through Ramu's own connection, decoded with WebCodecs in a WebView as Simlock's console does, instead of dropping to screenshots. Build it with the phone checks below: whether the phone's WebView decodes H.264 with WebCodecs, and the tunnel case itself, can only be tried on a physical phone.
- **Starting points for test devices:** **Save as starting point** on a thread's device would make a Simlock baseline (an app signed in, test data loaded) that the next thread opens from. Blocked on Simlock 0.6.0: a baseline starts only from `simlock lease --baseline`, its agent-device front cannot allocate from one, and agent-device cannot drive a lease it did not take, so a baseline device would lose the element tree. Reopen when Simlock's front takes a baseline.
- **Browser and computer use:** provider capability negotiation and more session-import sources. **Open on this phone** reaches only dev servers listening beyond the host's loopback; forwarding one loopback port to one paired phone (expiring, IP-bound, shown with its port) needs a security review first. Computer use on Windows and Linux waits for native capture, permissions and signing.
- **Host facts for agents:** `hostThreads.projects` could add each host's platform, architecture and description so `project_list` lets an agent recommend a host; it changes what a paired host learns, so it needs the same scrutiny as the rest of [host pairing](../SECURITY.md#host-pairing).
- **Activity tokens:** Cursor turns record tokens from the SDK's per-turn `usage` message (or the run result's `usage`); confirm it on a live turn with a paid Cursor login, which the 2026-11-15 attempt lacked. Claude, Codex, OpenCode (from each step of `opencode serve`) and Antigravity (ACP `usage`, checked live on 1.4.3) record tokens.
- **Helpers on another host:** `ramu_agent` with a `host` would mirror a helper's events into the parent live, which needs an event channel between hosts; a thread started there with its report covers the need until then.
- **Site screenshots:** a real capture from a release build beside each of the five steps in **From an idea to a live app** (`apps/site`). Claim "anyone can ship an app" only after the non-coder task under [Acceptance](#acceptance) has passed with real people.
- **Presenting from the phone:** **Present** a deck on a display the phone is connected to (AirPlay or a cable), with the speaker notes on the phone, as the desktop does with two displays ([Artifacts](guide/artifacts.md)).
- **Plugins:** `akalstack/ramu-plugins` and `akalstack/ramu-plugin-template` are on GitHub as private repositories; make them public together with `akalstack/ramu`, since Browse clones the index and their CI builds `ramu` from it (until then, CI needs a `RAMU_READ_TOKEN` secret). Run `pnpm --filter @ramu/site plugins:sync` before the site's build. Media services move to plugins when a service ships an MCP server that makes the file: an ElevenLabs plugin mapping speech, music and sound effects to its tools replaces its `MediaConnector` once it passes the same live checks. Whether Bitbucket and Azure DevOps stay first-party is decided by running the same pull request task through Ramu and through their CLIs with a plugin's skill, counting steps, failures and secrets that reached the transcript ([Plugins](guide/plugins.md)).
- **Games and 3D, later:** a physics library pinned beside three.js (Rapier) if games keep shipping their own; an App docked as a panel across a project's threads (an asset gallery, a level editor) if people ask for it; Unity checks through computer use on the editor window for games that never leave the engine; a Blender plugin for retopology and levels of detail.
- **Tools across hosts, later:** sending a plugin's or MCP server's key to another host, sealed to that host and confirmed with a matching number on both screens, if adding keys again proves the main friction (it reopens credential synchronization below and needs the review [host pairing](../SECURITY.md#host-pairing) had); installing from the phone, if approving on the host proves the friction; bringing in skills and servers from provider folders as Ramu's own so they travel (today a provider-folder skill stays on its host, and publishing it to Git lets it travel); and a server for several projects following each of them. ([On your other hosts](guide/plugins.md#on-your-other-hosts))
- **Ramu account, to go live:** `apps/account` runs at `account.akalstack.com` on a Neon database (`ramu_account`, Singapore) through Hyperdrive, with passkey, GitHub and Google sign-in configured. Remaining: a full GitHub and Google sign-in from the desktop and a phone, and Google's brand verification of the **Ramu** consent screen (Google Cloud project `akalstack-ramu` in the `akalstack.com` organization), which checks the [privacy notice](https://akalstack.com/privacy) (it lists what the service stores, as [Security](../SECURITY.md#ramu-account) does) and the [terms](https://akalstack.com/terms). ([Account](guide/account.md)). Later: cloud Ramu hosts attached to the account and listed in the host switcher, with the web app at `ramu.akalstack.com`.
- **Mobile dev builds:** `apps/mobile/package.json` builds `expo-video` from source, because its prebuilt binary does not match `expo-modules-core` 58.0.26 and a dev build crashed at launch. An `apps/mobile/ios` folder generated before that change needs `pod install` (with `LANG=en_US.UTF-8`) to pick it up. Building every module from source does not work: Xcode 27.2's Swift compiler crashes on ExpoModulesCore. Drop the override once `expo-video` ships a binary that matches.
- **Code quality:** about 140 `react-hooks/exhaustive-deps` disables name the trigger they are keyed on and are mostly deliberate; convert one only when touching it, after checking it neither loops nor refetches.

## Decisions and deferred scope

- **Certificate pinning:** not built. It needs a native transport replacement that cannot be verified without device builds. Reopen with a concrete threat that HTTPS pairing and host-identity checks do not cover.
- **Preference sync:** settings move between a person's hosts over host pairing, an export file, or an encrypted backup in a Ramu account or their own GitHub ([Identities and moving settings](guide/identities.md#moving-settings), [Ramu account](guide/account.md)); credentials and workspace state never move, and the account service cannot read backups.
- **Remote access:** devices reach a host over the LAN, a private network (Tailscale, NetBird, ZeroTier, WireGuard), SSH, or a tunnel: Cloudflare's quick tunnel, Tailscale Funnel or ngrok run by Ramu with the person's own tool, or one they run and name. A hosted relay and paid plans are deferred until there is a way to fund them; tunnels provisioned per host by a Ramu service are the cheapest option to revisit (free up to 1,000 tunnels).
- **Remote administration:** network access, pairing and device permissions are managed only at the host. A device's **Change settings** permission covers settings, not this; widening it needs reviewable changes and recovery first.
- **Codex call costs:** Ramu does not price Codex tokens from a table of its own. Published per-token prices change with each model release, and the lists outside OpenAI's own rate sheet disagree, so a built-in table would rank providers on figures that are wrong. Cost-aware Auto uses only costs a provider reports; a Codex API key, which reports tokens but no cost, ranks after subscriptions and after keys with a reported cost. Reopen if Codex starts reporting cost.
