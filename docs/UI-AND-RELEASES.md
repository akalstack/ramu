# UI components and desktop releases

Ramu uses shadcn/ui components in the current CLI default style (`base-nova`, built on Base UI rather than Radix) generated by CLI 4.21.4, Tailwind 4, and the existing workspace theme tokens. `components.json` maps the renderer's `@` alias. Add components with `pnpm ui:add <component>`; use `pnpm dlx shadcn@latest add <component>` to explicitly fetch the latest CLI. Review generated changes before overwriting locally customized components. Base UI differs from Radix: triggers take `render={<Button />}` instead of `asChild`, dialogs dismiss through `onOpenChange(open, details)` with `details.cancel()`, focus is set with `initialFocus`/`finalFocus`, and menu items use `onClick`.

Buttons, inputs, textareas, badges, tooltips, selection controls, dropdown menus, popovers, dialogs, and the command palette use shadcn primitives. Monaco editors, terminals, draggable workspace tabs, and textarea-anchored file/skill completions retain their specialized implementations. Tailwind preflight is omitted to preserve Monaco/xterm behavior. `ui.css` maps shadcn colors to Ramu's tokens; `styles.css` provides compact desktop sizing. Semantic success, error, and warning colors are shared with the diff theme.

Menus/dialogs enter in 100–140 ms, tooltips wait 350 ms, and switches move in 120 ms. Newly streamed assistant messages have a subtle arrival and generation cursor, without buffering or replaying saved transcripts. Reduced-motion preferences disable animations and smooth scrolling.

## Terminals, previews, and keyboard access

Terminal tabs represent groups: splitting adds a pane to the active group, and a new terminal gets a separate tab. Moving a pane to a new tab preserves its shell. Group membership and orientation persist with workspace UI state; older split layouts restore as a single group. Hidden groups keep running. Arrow keys, Home, and End navigate the group tabs. Terminals enable xterm's screen reader support and use native menus for selection-aware copy, paste, select all, and clearing scrollback.

Attachment previews offer zoom, actual size, fit, rotate, drag/keyboard pan, expand, previous/next attachment, copy, save as, and reveal. `+`/`-` zoom, `0` fits, `1` shows actual size, and Escape closes. Closing restores focus to the attachment that opened the preview. Attachment tiles have native menus before and after sending; Remove appears only for editable attachments. Selected text inside text previews retains the native text copy menu. Clipboard and save-dialog operations stay in the desktop main process.

Local Markdown file links in agent replies resolve against the chat's folders and open in the editor, including `file:` URLs and line/column suffixes. Missing or ambiguous files show an error rather than navigating the app. Sidebar, chat-pane, and terminal-panel resize handles support arrow keys, Home, and End as well as dragging.

## App icon and logo

The mark is a monoline "r" and a dot on a graphite tile; the dot blends the three accent colors, after *ramu* (blending into one mixture). The "ramu." wordmark uses the same rounded monoline strokes. Both are drawn as geometry rather than set in a font, so they render identically everywhere. `scripts/make-logo.py` generates `assets/icon.svg`, `assets/wordmark.svg` / `wordmark-light.svg`, and the README lockups `assets/logo.svg` (dark backgrounds) / `logo-light.svg`. Run `python3 scripts/make-logo.py assets && pnpm icons` to regenerate them and re-render `assets/icon.png` and, on macOS, `assets/icon.icns`. Forge uses `assets/icon` for packaged builds. The previous icon and logo are kept in `assets/archive/v1/`.

## Packaging

`pnpm dev` retains the existing electron-vite development loop. `pnpm package` invokes Electron Forge 8 and builds the main process, detached daemon, preload, and renderer before packaging. `pnpm make` creates platform-specific distributables under `dist/make`:

- macOS: DMG and ZIP.
- Linux: DEB and ZIP (build on Linux with the required system tools).
- Windows: Squirrel installer and ZIP (build on Windows with the required system tools).

pnpm uses a hoisted node_modules layout because Forge's dependency crawler expects physical dependencies. Forge rebuilds native dependencies for the target Electron version. A packaging hook fixes node-pty's spawn-helper executable permissions. The app is packaged without ASAR so its detached Node process and the Claude SDK's native executables can run directly from the installed app. `ELECTRON_RUN_AS_NODE` must remain enabled for the background runner.

macOS builds are unsigned locally. For signed/notarized release builds, provide `RAMU_SIGN_IDENTITY` and, for notarization, `APPLE_API_KEY` (key file path), `APPLE_API_KEY_ID`, and `APPLE_API_ISSUER`. Signing credentials are never stored in the repository. The GitHub Actions draft release workflow is documented in [RELEASING.md](RELEASING.md). No automatic update channel is configured.

The packaged app normally enables the existing macOS login runner on first launch unless disabled in settings. Isolated test profiles set through `RAMU_USER_DATA` do not register a login agent. Run the integration journey against a packaged executable with `RAMU_PACKAGED_EXECUTABLE=/absolute/path/to/Ramu node scripts/automation-smoke.mjs`; it exercises the same UI, daemon, schedule, review, and undo behavior without paid model calls.

Format on save defaults to enabled for new profiles; a saved choice remains respected. It uses project formatters before Monaco fallback. Language servers, live linting, preview tabs, and queued follow-ups remain enabled; AI completions and next-edit remain opt-in. App and schedule settings have no timezone input: recaps follow the current OS timezone and new schedules capture it when created.

Model favorites can be reordered by dragging their handles or using Alt+Up/Down on a focused handle. The saved order determines the numbered model-picker shortcuts. Search and unavailable models do not remove hidden favorites when reordering.

All Monaco surfaces use the same Electron native context menu family as text inputs, terminals, and attachments. It preserves the selected code, offers clipboard and relevant navigation/editing commands, and adds review comments in pair-review panes. File formatting uses the project formatter through the existing format command. Embedded review textareas retain the native text-editing menu.
