# Saved message drafts on desktop and mobile

Desktop implementation, mobile recovery/shortcuts and native acceptance remain unfinished. Current mobile behavior and attachment/storage boundaries are documented in [Saved message drafts](MESSAGE-DRAFTS.md). Let a person put an unsent message aside, compose something else, then restore it for review on desktop, iOS and Android. Follow [Architecture](ARCHITECTURE.md), [UI](UI.md) and the [root product and planning guidance](../AGENTS.md#planning-docs). Move shipped behavior into the feature guides, remove completed items and delete this plan when finished.

## Smallest usable delivery

While preparing a task with files and quoted context, a person chooses **Save draft**, gets an empty composer, sends a more urgent message, then opens **Saved drafts** and restores the original work. Support multiple saved drafts in both New thread and existing-thread composers. Saving or restoring never sends, queues, steers, creates a thread/worktree or resumes an agent. Keep the current automatic restoration of the active composer; an explicitly saved draft is a separate item the person can return to later.

Deliver this complete flow through the existing desktop and mobile composers. Text, existing supported context and completed attachments belong in the first delivery; unresolved uploads must have an explicit recovery state. Search, folders, synchronization and new editor capabilities are not prerequisites. Validate the representative task above on desktop and both native platforms, including restart and an offline host.

## T3 Code reference

The [T3 Code composer guide](https://github.com/pingdotgg/t3code/blob/9c161462c94f7d9d6d9169da5c841457cbadf213/docs/user/composer.md#prompt-stash), inspected on 2026-10-18 at revision [`9c161462c94f7d9d6d9169da5c841457cbadf213`](https://github.com/pingdotgg/t3code/commit/9c161462c94f7d9d6d9169da5c841457cbadf213), documents a desktop/web prompt stash. Its shortcut saves text and attachments; from an empty composer it restores one stash or opens a menu for several. Uploads must finish first; attached files require their original environment and expire after 24 hours, with **Attach again** recovery. Stashed context chips and quote comments are preserved.

Use the save/restore interaction as a reference, expressed through Ramu's existing controls and storage boundaries. This guide does not establish mobile stash support. Mobile saved drafts are proposed Ramu work. Do not inherit T3's attachment lifetime, shortcuts or storage implementation without checking Ramu's constraints; review licensing before copying source.

## Existing Ramu pieces to extend

- Desktop `apps/web/src/composer/drafts.ts` already persists active text by host and thread/project, flushes during workspace checkpoints and prunes automatic drafts after 30 days. It caps saved text at 200,000 characters. It is not a multiple-draft library or a complete attachment/context snapshot. Keep legacy active drafts readable and separate their pruning policy from explicit saves.
- `apps/web/src/composer/Composer.tsx`, `NewTask.tsx` and the existing thread view own the editing/submission surfaces. `composer/Attachments.tsx`, shared `chat/composerDraft.ts` and context/reference helpers already represent supported message parts. Reuse those representations instead of flattening references into display labels.
- Extend the mobile composer/library/store paths documented in [Saved message drafts](MESSAGE-DRAFTS.md). Preserve atomic moves, revision checks, legacy sidecars and native recovery slots. Complete missing-scope recovery, shortcuts and native acceptance through these same paths.
- Desktop `hostStorage.ts` provides host-scoped device storage. Keep drafts device-local and host-qualified on both clients. The offline outbox and server follow-up queue are separate delivery flows with existing semantics; saved drafts must never enter either automatically.

## Experience in Ramu

Add desktop **Save draft** and **Saved drafts** through the existing composer actions, with an empty state explaining that drafts stay on this device. Disable Save when there is no text, attachment or context. Derive a short preview title from content; do not require a name, model call or Settings visit. Show a quiet saved-count affordance when useful without adding a permanent toolbar row.

Desktop opens a compact menu or dialog using existing app components, spacing, semantic tokens and focus behavior. Each row shows preview, saved time, original thread/project and attachment/context availability, with **Restore** and **Delete**. Compose app controls outside `apps/web/src/components/ui/`; leave upstream primitives untouched. Add command-palette actions through the existing commands source. Offer `Cmd+S`/`Ctrl+S` only while the composer owns focus and no IME composition is active; file editors retain their Save behavior. Visible actions remain available without shortcuts.

Mobile uses the existing composer action sheet and a native sheet/list for saved items, within the four-tab navigation. Use shared mobile rows, icons, tokens, safe areas and accessible touch targets. A selected row can preview a long message and its context before restoring. Return focus to the composer with a sensible selection; opening or dismissing the list must not discard text, move the transcript unexpectedly or force the keyboard open. Hardware-keyboard shortcuts follow the same focus rules as desktop.

Default the list to the current host and composing scope, with **All drafts on this host** available in the same surface. Never mix hosts by display name or matching project/thread IDs. Restore to the original scope by default. An explicit **Use in this thread** can target another scope on the same host only after reviewing incompatible references; it does not silently switch projects, workspaces, providers or models. If the original thread/project was removed, retain readable content and offer this recovery action. Cross-host copying is deferred.

Saving persists a complete snapshot before clearing the active composer. If persistence fails, keep everything editable and show **Could not save draft** with Retry. Restoring into a nonempty composer offers **Save current and restore** or **Cancel**, rather than overwriting or concatenating work. Keep the saved item until the restored active draft is durably recorded, then consume it. Failures leave the saved source available. Delete offers Undo and only removes resources no longer referenced by active drafts, other saved items or delivery flows.

Keep normal Send/Queue/Steer actions and provider capability checks. A restored draft is ordinary unsent work, even while a turn runs or a usage limit holds it. Changes to thread model selection remain explicit. Provide English/Indonesian labels, keyboard and screen-reader navigation, meaningful status announcements, large-text layouts and reduced-motion behavior.

## Persistence, ownership and recovery

Extend the shared versioned draft records, validation and pure save/restore transitions under `packages/shared/src/chat/` for the desktop adapter and remaining recovery flows. A record needs a stable ID, revision, saved time, source host/scope, text, supported context/chip/quote metadata and attachment references with availability state. Preserve relevant explicit new-thread choices through the [workspace-defaults plan](WORKSPACE-DEFAULTS-PLAN.md), including default-versus-manual provenance; revalidate them before creation. Restoring a draft must not allocate paths, execute Git or infer new provider settings.

Use the desktop host store and mobile local persistence; device-local draft content does not become server `AppPreferences`, provider memory or agent events. Agents, workspace files and uploaded attachments remain on the owning execution server through the typed API. New server methods are needed only if attachment retention/validation requires them; extend existing file services, contracts and authenticated capability checks rather than introducing a draft server or provider-specific draft service. Older hosts must retain text/context restoration with truthful unavailable-attachment states.

Remaining desktop implementation and cross-client acceptance must resolve these correctness requirements:

- Make save/restore transactional or recoverable across the saved record and active draft. Serialize writes and use IDs/revisions so double taps, concurrent windows, delayed uploads and stale effects cannot duplicate a move, clear newer edits or delete the source prematurely. Capture the exact host/scope and composer revision before awaiting work; a late result never mutates the newly selected thread. Coordinate with the [voice-input ownership rules](VOICE-INPUT-PLAN.md#shared-state-insertion-and-resource-ownership).
- Block Save while uploads are pending, with an explanation and wait/cancel controls. Snapshot completed attachments and supported reference data together. Do not claim that saving metadata preserves file bytes. Audit current host attachment lifetime/cleanup and native temporary-file lifetime before implementing retention. Keep bytes in existing platform-owned storage where available, reference-count retained resources, and expose **Attach again** or **Remove** if unavailable. Never embed large base64 payloads in desktop localStorage.
- Saving and text restoration work offline. Restored uploaded files remain tied to their original host and require validation before submission; missing/revoked/deleted resources stay visible and block attachment submission until repaired or explicitly removed. Never omit them silently, fetch from another host or replay uploads twice on reconnect. Preserve captured quote/excerpt text even when source navigation is unavailable.
- Migrate existing active-draft formats additively, including mobile mention sidecars. Validate malformed/unknown versions without erasing unrelated drafts. Explicit saved drafts do not inherit automatic 30-day pruning or silent text truncation: validate against actual composer/storage limits before clearing, retain until consumed/deleted, and show a recoverable storage-full state. Choose a bounded item/byte budget from current storage limits and representative attachments; at capacity ask the person to remove an item, never evict an explicit save silently.
- Complete desktop Forget host and cross-client re-pairing acceptance with the [host-discovery plan](HOST-DISCOVERY-PLAN.md). Preserve stable host identity through route changes. Forget must explain removal of device-local active/saved drafts and attachment copies before discarding them; never migrate them to an unrelated host. App backgrounding, lock and process termination must preserve committed saves without promising recovery of uncommitted keystrokes.

## Implementation order and acceptance

1. Implement complete desktop active snapshots and host-scoped save/list/restore/delete through existing storage and composer paths. Reuse shared versioned snapshots and pure moves; extend them for desktop-only explicit branch/naming choices before capturing those choices. Preserve legacy text drafts, captured context and review/quote metadata. Design an atomic or recoverable move across active and saved records, including concurrent windows, storage denial/quota, interrupted writes and stale effects. Do not copy bytes into localStorage.
2. Compose desktop menus/dialogs and command-palette entries with app controls outside `components/ui/`. Add composer-focused Save shortcuts with IME guards. Restore into occupied composers only through Save current and restore; add Delete/Undo and scope-aware previews. Validate retained attachments on the owning host, keeping old-host and offline states explicit.
3. Complete mobile hardware-keyboard behavior and missing/deleted-source recovery. Offer **Use in this thread** only after reviewing incompatible references; preserve the readable saved source on cancellation/failure. Verify all supported entry points and delayed picker/upload transitions. Keep source navigation and scope identity accurate across host/project/workspace changes.
4. Run the representative task on desktop and physical iOS/Android with two hosts containing colliding IDs, then repeat after restart/background/reconnect. Verify native sheets, keyboard open/closed, IME, external keyboard, narrow/landscape layouts, large text, VoiceOver/TalkBack, light/dark and English/Indonesian. Cover new/existing threads, offline edits, removed scopes, missing attachments, cancellation, Undo and failed Send. Saved drafts must never execute on reconnect. Record native acceptance separately from browser previews.

For implementation, run tests and typechecks for affected shared/web/mobile/server packages. Desktop-facing changes require `pnpm build` followed by `pnpm test:desktop-smoke`, with no concurrent rebuild. Keep `scripts/smoke/desktop-smoke.mjs` as the only desktop startup check. Documentation-only edits need formatting and link checks; implementation changes need the scoped checks above.

## Later options

Cross-device synchronization, cross-host copying, reusable prompt templates, tags/search and sent-prompt history recall need separate demonstrated workflows. They are not required to finish this plan. Continue dictation, workspace selection and queued-message editing through their existing plans/services instead of folding them into a general draft-management system.
